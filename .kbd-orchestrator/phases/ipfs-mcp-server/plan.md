## 1. DECISIONS (aligned to addendum revision 3)

F4 is unchanged: `ipfs mcp` is a CLI-only local command in the fork's `ipfs` binary (package `github.com/ipfs/kubo/mcp/server`, root module), RPC-only to a running daemon through `client/rpc`, never opening the repo. No change adds a daemon listener or a Kubo repo config key (`config/`, `docs/config.md`), and none changes `/api/v0`, the gateway, the default CID recipe or wire behavior. The plan **does add new configuration**: the `ipfs mcp` flags and its `--config` file (principals, LLM backend, agent endpoints, confirmation resolvers, embeddings, listen address, reserved-port rule; schema in `mcp/contract/config/`). That configuration is subject to the config-docs and feature-off-switch constraints: section 4a lists each option group, its off switch, where it is documented (`docs/mcp/config-reference.md`, generated from the schema) and the test that runs it disabled. If any change touched a Kubo repo config key, that change would add its `docs/config.md` entry; none is planned. `noagent` compiles out everything except MCP, and `nomcp` compiles out all of it.

### D1. Topologies

- **Topology A (primary, this phase).** `ipfs mcp --http` serves `/mcp` (Streamable HTTP), `/agui`, `/a2a` and `/.well-known/agent-card.json` on one listener, default **`127.0.0.1:5050`**, overridable by `--http=<multiaddr>` and env. `--agui` and `--a2a` are off by default and are mounted only when an LLM backend is configured. One `AuthVerifier`, one scope map, one confirmation gate, in-process. Path-scoped authorization prevents cross-protocol token confusion (falsifier G9-4).
- **Topology B (conditional).** UAR hosts AG-UI and A2A and calls `ipfs mcp --http` as a configured `kind: uar` principal (read-only by default, `egress_ack`, native prompt, check-uar). **Stdio-spawned UAR is forbidden**: the shipped profile never spawns `ipfs mcp`, and `ipfs mcp` refuses `contentEgress` tools to a stdio client whose `clientInfo` identifies UAR (a misconfiguration guard, not a security boundary). **Gate:** UAR's conformance items contained in a published, installable UAR release (tag plus image digest or native package) by the **end of Round 4**; otherwise topology B is deferred and reported unmet, and topology A is unaffected.
- **Cost of two topologies.** Topology B accounts for `uar-conformance-request`, `uar-integration-spike`, `agentic-uar-integration`, and the check-uar and stdio-guard parts of `mcp-agent-principal-enforcement`: 3 changes and about 14 tasks, plus a standing coupling to UAR's settings-API shape (check-uar fails closed when it changes). The plan keeps it because the operator chose "Both"; it is conditional so it cannot delay topology A.

### D2. G9 and G10: AG-UI and A2A in `ipfs mcp`, L3 loop and proxy

- The adjudicated CRITICAL stands: under the goal-fit gate with undelivered UAR items uncredited, UAR-hosted-only scores goal fit 2 and is excluded; (a) wins 51 to 49. The operator then chose (a) plus L3.
- `mcp-llm-proxy-loop` (N11): `--llm-base-url`, `--llm-model`, `--llm-api-key-env`/`--llm-api-key-file` (or config keys); **no default URL or model**; a literal key fails validation; unset means no agent surface is mounted and no model call is ever made. An OpenAI-compatible chat-completions client with `tools` (UAR's `/v1/chat/completions`, `uar:src/server.rs:1901`, or any other server). A bounded loop (step, token and wall-clock limits) over the caller's enabled contract tools only, with no shell, filesystem or network tools.
- **Egress, topology A:** enforced in-process. A `contentEgress` result is included in a model request only if the backend host is in `egress_ack`; otherwise the model gets "Content not sent: `<host>` is not in egress_ack." With a UAR backend, check-uar also verifies UAR's effective upstream provider per session. *(Amended 2026-10-09, ADR-0008: that per-session check moved to `agentic-uar-integration` task 1.5, deferred with topology B; until then a UAR backend is an ordinary `egress_ack` host.)* **Egress, topology B:** only through the `--http` principal's `egress_ack` and check-uar. **Stated limitation:** Kubo cannot see what an acknowledged endpoint does with data (a loopback server forwarding upstream, a UAR whose provider is unreadable, stdio MCP hosts using their own models, WebMCP in the browser). The plan does not claim "no content leaves the machine" in general.
- `mcp-agui-endpoint` (N12): `RunAgentInput` in, spec events over SSE; a pending confirmation ends the run with `RUN_FINISHED` `outcome: {type: "interrupt"}`; resume carries `resume: [{interruptId, status, payload}]`. `mcp-a2a-endpoint` (N13): A2A 1.0 agent card and JSON-RPC (`message/send`, `message/stream`, `tasks/get`, `tasks/cancel`), `TASK_STATE_INPUT_REQUIRED` for pending confirmations and `TASK_STATE_AUTH_REQUIRED` for insufficient credentials; no A2A message can approve a write.
- **Protocol implementation:** hand-written types from the spec schemas over `net/http`; an SDK (`a2a-go/v2`, a community AG-UI SDK) only if G9-1 schema validation fails and the operator approves the root `go.mod` addition after a measured dependency review.

### D3. Human gate (part of ADR-0004; `native-confirmation-prompt`, N14)

Clients that can elicit keep elicitation. For every principal that cannot elicit, writes and destructive calls wait in a broker (expiry is denial, exactly-once execution) for a **native OS prompt with a presence factor** a same-user background process cannot simulate: the paired IPFS Desktop confirmation window (N6) when Desktop runs; otherwise a macOS LocalAuthentication prompt (Touch ID or password) or a Linux polkit authentication-agent prompt raised by `ipfs mcp`. Both name the tool, the CID, path or name, and the effect. `ipfs mcp confirm <id>` exists only for headless servers behind `--confirm=cli`, needs a TTY, and warns that same-user processes can reach it; under it every write principal needs the operator assertion `shell_capable: false`. Where no resolver exists (Windows, Linux without the polkit action, unpaired Desktop), writes from non-eliciting principals are refused (`confirmation_unavailable`). The two-step token is never accepted from a principal that cannot elicit (`mcp-pinning-with-confirmation` 1.5). **AG-UI chat interrupts** answered by a user gesture in the island count as the gate for the `ui` principal, as elicitation does; destructive tools additionally raise the native prompt; this is revisited if G11-3 is falsified. Shell-capable tools are refused for write principals: the topology-A loop has none, and check-uar refuses write groups when UAR reports `terminal_exec` or a non-Kubo MCP server.

### D4. Principals and check-uar (`mcp-agent-principal-enforcement`, N8)

Principal kinds `human-mcp`, `ui`, `a2a`, `uar`; read-only by default; write and destructive groups granted by name; unknown tokens get nothing; `contentEgress` tools refused without `egress_ack` (structured error, never an empty result). check-uar runs at startup, at every session initialize and on reported settings change: agent-card version at or above the pinned minimum from a published release, authentication required, effective model, embedders and governance, shell-tool refusal; unreadable settings fail closed unless the operator records `check: assert`. A `0.0.0.0` UAR bind is not detectable from loopback; the shipped profile (N3) is the supported configuration.

### D5. G11: chat island and Desktop

`mcp-ui-component-library` gains the chat primitives (registered change, appended tasks 2.1-2.3). `agent-chat-island` (N4): `<ipfs-agent-chat>`, a shadow-root React 19 + Tailwind 4 + shadcn right-side sliding sidebar with the A2UI renderer and an AG-UI client, Promethity tokens and fonts bundled, no remote assets, no `unsafe-eval`, talking **only** to `ipfs mcp` `/agui` behind the origin allowlist (`webui://localhost`, `http://127.0.0.1:5001`, `http://localhost:5001`, configured subdomain-gateway origins) and a `ui` principal token. `webui-agent-chat` (N5): fork `src/agent-chat/**` launcher and off-by-default toggle, after `webui-webmcp-integration` (shared Settings). `desktop-agent-chat` (N6): CSP for `webui://localhost`, `webSecurity` re-enabled, `safeStorage` token bridge, the paired confirmation window; ui-ux-engineer owns it, security-reviewer reviews. Flip: if G11-1 (shadow-root isolation) fails, a Desktop-only view in its own origin (U3).

### D6. G12 re-scored under the goal-fit gate; decision E6 (embedding and storage in `ipfs mcp`)

Verified (2026-10-09): `surrealdb.go` is a network client; in-process SurrealDB from Go exists only through `surrealdb.c.go`, which links `libsurrealdb_c.a` via cgo (https://surrealdb.com/docs/reference/golang/embedding); Kubo has no cgo; SurrealDB is BSL 1.1; `surrealdb.go` v1.7.0 is Apache-2.0 (addendum, `proxy.golang.org`); UAR has no `/v1/embeddings` route (`grep` over `uar:src/server.rs`) and `/api/ingest` uses one hardcoded knowledge base. The operator requires both embedded and remote modes (Q10).

Re-score with the addendum weights (goal fit 3, Kubo surface 2, rules fit 3, license/build 2, maintenance 2, search 1; max 65). Undelivered UAR items are not credited; an option lacking either mode or limited to UAR-routed content has goal fit at most 2 and is excluded.

| Option | Goal fit | Surface | Rules | License/build | Maint. | Search | Weighted |
|---|---|---|---|---|---|---|---|
| UAR embeds and stores (topology B only, nothing credited) | 2: gated on a UAR release; topology-A content not covered; KB not CID-keyed | | | | | | excluded |
| cgo `surrealdb.c.go` linked into `ipfs` | 4 | 1 | 3 | 1 | 1 | 4 | 31 |
| Remote-only from `ipfs mcp` | 2: no embedded mode | | | | | | excluded |
| **E6: `ipfs mcp` embeds and stores in both topologies; embedded = managed local `surreal`; remote = URL** | **4** (WebMCP adds not automatic) | **2** | **4** | **4** | **2** | **4** | **44** |

**Decision: E6.** `ipfs mcp` is the component that embeds and stores, in both topologies (in topology B, UAR's writes also pass through `ipfs mcp`, so UAR-side embedding is not needed). Mechanism per mode:

- **Embedded:** `ipfs mcp` starts `surreal start --bind 127.0.0.1:<ephemeral> surrealkv://<operator data dir>` from an operator-supplied absolute binary path (no PATH lookup, never downloaded or shipped; 3.3.0 is installed here), with per-start random credentials in a 0600 file, a minimum-version check, stop on exit and crash cleanup (G12-3). "Embedded" means supervised and private to `ipfs mcp`, not linked in-process.
- **Remote:** operator URL, namespace and database; credentials from env or file; no default.
- **Client:** the standard library over SurrealDB's HTTP API by default (no new module). `surrealdb.go` v1.7.0 is used only if its build probe passes (`CGO_ENABLED=0 make build`, binary delta under 3 MB; G12-1) **and** the operator approves it in Round 0 (R2), because operator answer 2 covered go-sdk only.
- **Embedder:** operator-configured OpenAI-compatible `/embeddings` endpoint, host checked against `egress_ack`, no default.
- **Trigger:** opt-in (`embeddings.auto` off) after a successful `ipfs_add` from any `ipfs mcp` transport, MIME allowlist and size cap, plus `ipfs_index_cid`. WebMCP browser adds are not indexed automatically (stated limitation).
- **Deletion:** only when `pin ls --type=all <cid>` shows no pin of any type; after `repo_gc`, only CIDs GC removed; `ipfs_index_reconcile` for out-of-agent unpins. A daemon-wide hook stays refused.

**Deviation from the addendum change set, with reason:** the addendum's N7 (store, both modes, embedder, trigger, tools, deletion; about nine tasks) does not fit one agent session (planning rule 4). It is split into `mcp-embeddings-surrealdb` (N7: store, both modes, embedder) and `mcp-embedding-index-lifecycle` (N7b: trigger, index tools, pin-aware deletion, reconciliation). N7b runs in Round 8 after N7 (Round 7) and writes its own docs section; after review round 2 `mcp-user-docs` also waits for it (Round 10). Result: 22 + 13 = 35 changes instead of 34.

### D7. Ports (operator, 2026-10-09)

No component defaults to 4000 (liter-llm), 1906-1908 or 50051 (UAR), 8181/8081 (openai-proxy), 11434 (Ollama), 23001/28000 (SurrealDB), 4545/4546, 5173, 5432, 6379, 4001, 5001 or 8080 (OrbStack holds 8080 here).
