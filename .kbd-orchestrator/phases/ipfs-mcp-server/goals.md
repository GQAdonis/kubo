# Goals

- G1 Architecture decision by assessment with adversarial review: evaluate every placement for MCP support (ipfs CLI subcommand, separate binary/module over the RPC API, daemon-hosted endpoint alongside RPC/gateway, plugin, out-of-tree package, other) against Kubo stability and user-agency rules, security, distribution and maintenance cost; record the chosen option and rejected alternatives as an ADR
- G2 MCP server exposing IPFS operations to agents (add/get/cat, pinning, IPNS publish/resolve and keys, MFS, DAG, CAR import/export, routing/provide, node status) with accurate tool annotations and structured output, driven by one shared tool contract in mcp/contract
- G3 Transports: stdio for local agents and Streamable HTTP for remote use, with authentication, loopback-by-default binding, Origin/DNS-rebinding protection, and an off switch for every capability
- G4 MCP App with UI/UX: React 19 component library that is also an A2UI v0.9 catalog, served as ui:// resources, WCAG 2.2 AA, light and dark
- G5 agentskills.io-compliant skills for push/pull, pinning, IPNS, MFS, DAG/CAR and troubleshooting, packaged as plugins and marketplaces for Claude Code, Codex, OpenCode and Kimi Code
- G6 No break to /api/v0, the HTTP gateway, the default CID recipe or wire compatibility; no tracking; no silent CID injection; destructive operations gated; docs and tests for every feature and its disabled state
- G7 Work is executed by the kubo-ipfs-agentic agent team with independent security and quality review at the phase boundary
- G8 WebMCP support in the IPFS Web UI (ipfs-webui): register IPFS tools via WebMCP (`document.modelContext`, with `navigator.modelContext` fallback) so agents in any WebMCP-capable host (Kimi desktop, Codex desktop, Chrome origin trial, other containers/browsers) can use the node through the Web UI; assess placement (ipfs-webui fork vs injected script vs Desktop wrapper), how Kubo/Desktop pin and serve the resulting Web UI CID, reuse of the shared tool contract, feature detection and an off switch, and host support evidence

- G9 AG-UI and A2A endpoints for the IPFS services, so agents and agent UIs can drive IPFS agentically (streamed AG-UI events for interactive UIs; A2A for agent-to-agent delegation); assess placement (daemon, `ipfs mcp` process, separate service, UAR-hosted), auth, and how they reuse the shared tool contract and confirmation gate
- G10 LLM backend for agentic behavior behind the AG-UI/A2A endpoints: proxy to an operator-configured Universal Agent Runtime instance (`/Users/gqadonis/Projects/prometheus/universal-agent-runtime`) or an operator-configured OpenAI-compatible server with API key; no default endpoint, off unless configured, credentials never hardcoded
- G11 Chat interface in IPFS Desktop and the IPFS Web UI: a right-side sliding shadcn/ui sidebar for AI chat about and with the user's node, rendering A2UI components wherever appropriate (shared A2UI catalog from mcp/ui), with tool calls subject to the same confirmation gate

- G12 Embeddings for uploaded documents: optional, configuration-driven automatic embedding of content added through the agent surfaces (chunking, model and dimension choice, which content types, when to embed), stored in SurrealDB with vector search, supporting both embedded and remote SurrealDB modes; off unless configured, embedding providers operator-configured (local or remote, never a hardcoded endpoint), and no content leaves the machine without explicit operator configuration
