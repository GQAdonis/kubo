## Backend

- **Backend:** `openspec` (OpenSpec 1.14.1 via the managed runner; refresh receipt `status: refreshed`, `latestVerified: true`, no authored paths changed).
- **Task driver:** `kbd-apply` (`begin-task` / `end-task` per task; `verify` / `archive` only after the phase gates pass). Bare `/opsx:apply` is never used.

- **Order rule:** a task starts only when every prerequisite change (its `after:` list in TASK MODEL ASSIGNMENTS, checked by `openspec/tools/check_plan_deps.py`) is complete. Round 0 (`team-ownership-grant`) runs alone.

Parallel rounds (R4 in particular) run in separate git worktrees with the merge order stated in the plan.

## QA and review (phase boundary only)

No per-task or per-change tests, refinement or reviews. After every production change is complete: one production-path integration gate (`make build`, `make -O test_go_lint`, `make test_unit`, targeted `test/cli` MCP tests against a real daemon on dynamically chosen non-default ports, JS package builds and tests), then one cumulative `/refine-validate` and one cross-family `/adversarial-review --mode diff` (`dispatch-judge.sh`, `gpt-6.1-sol` via liter-llm on :4000; run the packet builder with the timeout-wrapped `pk` from the session scratchpad if `pk search` hangs). G7 is blocking: if the cross-family judge cannot run, the phase records `pending_review` and does not complete. Then `kbd-apply verify` and `archive` per change.

## Lessons the dispatched work must respect (prior-context.md)

- The operator approves merges, tags and machine-level changes explicitly; one batched approval question at the phase boundary (task `team-ownership-grant` 1.1).
- The operator merges every PR and wants full KBD status at the end of every turn; operator-only actions (tags, repos, live-data changes) are asked explicitly.
- Tests discover their environment (ports, binaries, daemons) instead of encoding one checkout's state.
- Never call a CLI that takes a lock from inside an operation that already holds it; never paper over such a failure with a default value (applies to `ipfs mcp` and `repo.lock`).
- Every external integration (Kubo daemon, Ollama/OpenAI-compatible server, SurrealDB, UAR) gets at least one test against the real service before it is claimed done.
