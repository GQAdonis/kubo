## 8. RISKS CARRIED INTO EXECUTION

- The settings route is a remote write surface that changes egress; anyone holding the cloud `admin` bearer can repoint the backend; typed confirmation is UI-only (D2).
- Default-on WebMCP read tools disclose node content to in-browser agents of the console origin (accepted by `5f019f0df`).
- The chat `ui` token stays in `localStorage` on the console origin (operator decision 2026-10-10); with origin isolation no gateway content shares that origin, but any XSS in the Web UI would read it. `settings-security-review` rules on it (W7).
- Kimi sessions run with `--auto` (section 10). Outward actions are prevented by the launch environment and detected afterwards by the driver, not prevented by Kimi itself. A session that finds a credential the hardening missed could still act; the post-session check would catch it only after the fact.
- The Round 7 security pass sees the Web UI before the rebrand finishes; the gate's `security-reviewer` covers the rest.
- LKE runs the Round 8 candidate image from OG-12 until OG-9. `lke-agent-settings` 1.8-1.9 and gate 1.5 therefore test that image, not the merged binary; the merged binary reaches LKE only at OG-9, checked by `promethity-delivery` 1.2 (smoke) and 1.7.
- Three planned single-replica outages (OG-6, OG-12, OG-9, plus OG-13's sidecar restart) on a node that already had one rollout outage (R9).
- The new Secrets are created by hand, outside GitOps; a cluster rebuild from git alone would lack them, and `optional: true` means the agent features stay off rather than the pod failing.
- Reviewer findings are relayed by the architect because the Claude Code reviewer roles are read-only. The relay is verbatim and the reviewer's raw output is saved beside the findings file.
