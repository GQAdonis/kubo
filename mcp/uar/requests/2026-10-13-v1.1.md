So the operator's report holds for the working tree on items 1, 4, 5, 6 and 8, and mostly for 3 and 7; it does not yet hold for item 2 or for the release. Kubo's gate counts none of it until it ships in a published release. Meanwhile four gaps that Kubo goal 2 (topology B: UAR hosts AG-UI and calls `ipfs mcp --http` as a tool server) needs are not in the working tree at all: per-agent external MCP binding with a run-time credential, remote skill upload, confirmation of elicitation on globally registered servers, and documented AG-UI interrupt shapes.

This request asks for one release that closes both: commit the working tree, close the remaining gaps in #379 items 2, 3 and 7 listed above, ship the four gaps, and publish it as `v1.1.0` with an OCI digest.

## The gate rule (unchanged from #379)

Kubo counts an item as delivered only when it is contained in a **published, installable UAR release** — a git tag on the UAR repository plus an OCI image digest (`sha256:...`) built from that tag — and its acceptance check below passes against that artifact, installed as published, with no source build and no patches. Merged-but-unreleased work does not count. This is the same rule #379 states; this follow-up names the release `v1.1.0`.

If the release does not arrive, Kubo closes its phase with goal 2 carried open (decision D13). Topology A (`ipfs mcp` serving AG-UI itself, UAR usable as an OpenAI-compatible model backend via `/v1/chat/completions`) is unaffected either way. The uncomfortable version, stated once: if the gate holds with no release, this phase repeats ADR-0008 — the UAR integration stays a NO-GO and is reported as unmet, again.

When the release lands, Kubo pins the tag and digest in `mcp/contract/agentic/uar-preflight.json`, sets the `check-uar` minimum version, and runs the real-service test (`agent-backend-uar` 1.5) against the published artifact.

## How to run the checks

The checks assume a UAR instance started from the published `v1.1.0` artifact with its documented configuration for a local, authenticated deployment:

```bash
export UAR=http://127.0.0.1:<uar-port>        # the instance under test
export UAR_TOKEN=<a valid user bearer token>   # for authenticated calls
export UAR_ADMIN_TOKEN=<an admin token>        # for the admin/settings APIs
```

The AG-UI event schemas come from the published `@ag-ui/core` package; validation can use any JSON Schema validator (for example `npx ajv-cli validate`). The #379 checks referenced in item 6 are the ones in `mcp/uar/requests/CONFORMANCE.md`, items 2, 3 and 7.

## Requested items

### 1. Commit the working tree and release v1.1.0 with an OCI digest

- **Observed:** the latest plain tag is `v1.0.0` (`9e967a86`, 2026-07-11); HEAD is `b4244aea`; the working tree carries large uncommitted and untracked work that implements #379 items 1, 4, 5, 6, 8 and 9 (for example untracked `src/uar/api/agui.rs` and `src/uar/api/effective_settings.rs`, the `/.well-known/agent-card.json` path, the deny-by-default CORS allowlist, and `src/mcp/interaction.rs` elicitation). None of it is reachable from any published artifact.
- **Requested:** commit the working tree, tag the result `v1.1.0`, and publish an OCI image built from that tag with its `sha256:` digest recorded in the release notes. The release is the vehicle for #379 items 1, 4, 5, 6, 8 and 9.
- **Acceptance check:**

  ```bash
  git ls-remote --tags https://github.com/Prometheus-AGS/universal-agent-runtime 'refs/tags/v1.1.0'
  # start the published image by digest, then:
  curl -sf "$UAR/.well-known/agent-card.json" | jq -r '.version'
  ```

  Pass: the tag exists; the image runs when pulled by the digest recorded in the release notes; the agent card prints `1.1.0` (#379 item 9) and is served at `/.well-known/agent-card.json` (#379 item 1). Any step failing fails the item.

### 2. Bind an external MCP server to an agent with a run-time credential

- **Observed (HEAD `b4244aea`):** an external MCP server can only be registered globally (`PUT /api/uar/mcp/servers/{name}`), and its `Authorization` must be a `secret_ref` naming an environment variable in UAR's own process environment (`src/mcp/config.rs:71-83, 152-178`); per-run `mcp_servers` with a direct URL are loopback-http only (`src/uar/turn/host/mcp.rs:209-225`); an agent's `extensions.mcp_servers` can only narrow servers already bound (`src/uar/api/policy_intersection.rs:516-540`). Consequence: the `ipfs mcp` bearer must sit in UAR's process environment, and a credential that rotates or is scoped to one agent or one run cannot be expressed.
- **Requested:** a documented way to bind an external (non-loopback) MCP server to a specific agent, with the server's credential supplied at run time — in the bind or run request, or a reference to a credential store entry created over the API — instead of requiring it in UAR's process environment. We do not prescribe the shape; the check tests observable behavior only.
- **Acceptance check:**
  1. Stand up a test MCP server on a non-loopback-reachable URL that requires `Authorization: Bearer <secret-A>` and logs every inbound request with its headers.
  2. With `<secret-A>` present in **no** UAR environment variable, use the documented API to bind that server to a newly created agent, supplying `<secret-A>` at run time through the documented mechanism.
  3. Run the agent so that it calls a tool on the test server; read the test server's log.

  Pass: the test server's log shows the tool invocation carrying `Authorization: Bearer <secret-A>`; the binding names that agent and no other agent can invoke the server. Fail if any step requires the credential in UAR's process environment, or if the server is reachable only on loopback.

### 3. Remote skill upload

- **Observed (HEAD `b4244aea`):** skill CRUD exists at `/api/uar/skills` and bindings at `/api/agents/{id}/skills`; agentskills.io `SKILL.md` is parsed, but `POST /skills/import` only previews a **server-local filesystem path** and stores nothing (`src/uar/api/skills.rs:441-524`). There is no way to push skill content (Kubo's `mcp/skills/**`) to a remote UAR over its API.
- **Requested:** a documented endpoint that accepts skill content in the request — an archive or a `SKILL.md` body — validates it, and stores it so it can be bound to an agent; or, failing that, a documented server-side install path plus an API that lists installed skills so a client can verify the install. The content-carrying endpoint is strongly preferred: Kubo runs UAR on a different host from the files.
- **Acceptance check:**
  1. From a client host that has no shared filesystem with the UAR host, upload a `SKILL.md` (or archive) for a skill named `uar-check-skill` over the documented API.
  2. Bind the skill to an agent and read it back (`GET` the skill and the agent's bindings).

  Pass: the upload succeeds over HTTP with no server-local path involved; the read-back returns the uploaded body content and the binding lists `uar-check-skill`. Fail if the only install path is a server-local filesystem operation.

### 4. Elicitation for globally registered servers (and `shared_transports_enabled`)

- **Observed:** HEAD's MCP client advertises no elicitation capability (`src/mcp/registry.rs:698, 726, 834`); the WT implements elicitation (`src/mcp/interaction.rs:178-213`) and surfaces it as an AG-UI interrupt. Whether that channel reaches **globally** registered servers (the `PUT /api/uar/mcp/servers/{name}` path, not per-run servers) is unverified, and the `shared_transports_enabled` setting's effect on it was never checked. This is the load-bearing item for Kubo: `ipfs mcp` confirms every write by elicitation, so without it every Kubo write tool invoked through UAR fails.
- **Requested:** confirmation, backed by the check below, that a globally registered MCP server gets the elicitation channel; and documentation of how `shared_transports_enabled` interacts with elicitation (which value is required, or that both work).
- **Acceptance check:**
  1. Globally register a test MCP server (admin `PUT /api/uar/mcp/servers/{name}`) that logs the client capabilities it receives at `initialize`, and whose single tool sends `elicitation/create` before returning.
  2. Bind it to an agent, run the agent through the AG-UI path so the tool is called, answer the interrupt with accept; repeat with decline.
  3. Run the whole check under the instance's default configuration; if `shared_transports_enabled` is non-default in the shipped configuration, run it once with each value.

  Pass: the logged client capabilities include `elicitation`; the run surfaces an interrupt carrying the elicitation message; the test server receives `accept` with the submitted content in the first case and `decline` in the second, for each configuration value the documentation blesses. Fail if elicitation works only for per-run servers, or if one `shared_transports_enabled` value silently drops the elicitation request without documentation saying so.

### 5. An AG-UI agent path and documented interrupt shapes

- **Observed:** HEAD has no endpoint that accepts a `RunAgentInput` (`POST /api/uar/runs` plus `GET .../stream?stream_mode=agui_spec` uses `CUSTOM uar.*` events for approvals). The WT has untracked `src/uar/api/agui.rs` with `POST /api/uar/ag-ui/agents/{agent_id}`, which emits standard events and interrupts with `reason: "tool_approval" | "mcp_elicitation"`, rejects frontend tools with 400, and emits no CUSTOM or A2UI events. Because this exists only uncommitted, Kubo cannot write its interrupt translation (`agent-backend-uar` 1.3) against a stable shape.
- **Requested:** the AG-UI agent path shipped in `v1.1.0`, documented, with its interrupt shapes pinned per release: the `reason` values (at minimum `tool_approval` and `mcp_elicitation`), the interrupt payload fields, and the resume payload shape (the `ElicitResult` or its documented equivalent), so a proxy can translate them without reading UAR source.
- **Acceptance check:**
  1. `POST` a `RunAgentInput` (validated against `@ag-ui/core`) to the documented agent path with `Accept: text/event-stream`, for a task that needs an approval-required tool (a globally registered test server as in item 4 suffices).
  2. Validate every received event against the `@ag-ui/core` schemas; record the interrupt event.
  3. Send the documented resume payload approving the interrupt; in a second scenario, deny it.

  Pass: every event validates; the run ends or pauses with an interrupt whose `reason` is the documented `tool_approval` value and whose payload matches the documented shape; the approving resume runs the tool exactly once and the denying resume never runs it; no `CUSTOM` event is the only carrier of the approval. Fail if the interrupt or resume shape differs from the documentation, or if the shapes are not documented.

### 6. Verify #379 items 2, 3 and 7 against the published release

- **Observed (working-tree audit, 2026-10-13):** item 2 is partial (gRPC maps InputRequired to `working` at `a2a/grpc.rs:369`; `TASK_STATE_AUTH_REQUIRED` is never produced); item 3 is mostly done but `GovernanceBypassed` does not exclude A2A ingress when governance is off; item 7 is mostly done but `k8s/opentofu/configmap.tf` and the docker-compose dev and test files keep unsafe defaults. See the table under "Why we are asking".
- **Requested:** run the acceptance checks for #379 items 2, 3 and 7 — quoted verbatim in `mcp/uar/requests/CONFORMANCE.md` — against the published `v1.1.0` artifact, and record the results in the issue. Kubo re-runs the same checks on its side before pinning (`agent-backend-uar` 1.5).
- **Acceptance check:** the three #379 checks as written in CONFORMANCE.md, executed against the published `v1.1.0` image or package with no source build.

  Pass: item 2's two task states validate against the A2A 1.0 schema with the schema's exact input-required and auth-required values; item 3's tool runs zero times before approval, exactly once after approval, and zero times after denial, with the governance gate both enabled and disabled; item 7 shows every listener on `127.0.0.1` or `::1`, zero non-loopback outbound connections during the capture, a "no model configured" failure (or refusal to start) with no model set, and 401 for an unauthenticated request under every shipped configuration. Any deviation fails the item and blocks Kubo's pin.

## What Kubo does on its side

Unchanged from #379, restated for context: Kubo treats UAR as a configured principal of `ipfs mcp --http`, read-only unless the operator grants write groups; requires a human-presence prompt for every write UAR requests; refuses node content to UAR unless the operator acknowledges UAR's model and embedder hosts (`egress_ack`); and runs `ipfs mcp check-uar` fail-closed against the pinned release. In this phase Kubo additionally proxies AG-UI runs to the item-5 path behind its own `/agui` endpoint and translates the item-5 interrupt shapes into its own (`agent-backend-uar`, ADR-0010).
