# UAR v1.1.0 Kubo integration contract

Status: implementation candidate; publication and acceptance receipts pending. A tag alone does not establish OG-4. The immutable manifest digest, architecture digests, workflow commit and published-image acceptance receipt must be attached before declaring this release accepted.

## Authenticated startup and deployment
Default native/image startup binds loopback, requires authentication, has no configured model and disables remote memory/embedding calls. Configure a model deliberately before inference. Development/test Compose leave LLM_MODEL empty unless supplied. config.test.yaml requires authentication. OpenTofu requires authentication and defaults memory to disabled with the local BGE embedding provider; model selection is empty until configured.

Explicit deployment profiles retain their selected network listeners, remote databases and infrastructure. Those configured connections are intentional deployment behavior. The five-minute zero-egress and loopback gate applies to default startup; deployment profiles are checked for authentication, effective configuration and their selected infrastructure. Do not interpret a selected remote database as a zero-egress default.

## A2A and skill roles
A2A 1.0 JSON-RPC is exposed at /a2a/v1/compiler and /a2a/v1/agents/{agent_id}. Supply A2A-Version: 1.0 and verified bearer or API-key credentials. With required HTTP authentication, a missing credential can be rejected by middleware as an empty HTTP 401 before an A2A envelope is produced. Handler-level authentication and authorization errors carry the documented JSON-RPC response; gRPC uses its status codes. Official lf.a2a.v1.A2AService is exposed on the configured gRPC listener alongside legacy a2a.AgentService. See the public /.well-known/agent-card.json for supported bindings. Streaming, push and extended cards are unsupported unless explicitly advertised. Legacy /.well-known/agent.json and legacy endpoints remain compatibility surfaces with their historical wire shapes.

The operator alone configures required existing credential roles:

```yaml
security:
  jwt_required: true
  skill_required_roles:
    protected-skill:
      - user
      - kubo-maintainer
```

Every listed role is required. Skill documents and request metadata cannot set this policy or mint roles. A protected skill explicitly selected by the target agent's policy.skills.prefer is checked before task reservation. Missing roles return HTTP 403 with the existing JSON-RPC authorization error or gRPC PERMISSION_DENIED. Automatic matching and activation use the same host-derived eligibility. Authenticated continuation captures current roles; a previously privileged task ID grants no new privilege. Native `activate_skill` exposure follows the effective skill policy, even when ordinary tools are disabled. The native control retains its existing required approval; approving the control does not grant a missing skill role. The resumed request is checked with its currently verified credential.

## Trusted-host MCP setup
Configure the issuing service identity in UAR's operator configuration. The issuer, subject and tenant must match the verified credential exactly; a request cannot declare itself a trusted host. Use the deployment's existing JWT verifier and issuer credentials. The issuer-signed JWT payload must contain `uar_credential_kind: "issuer"`; a JOSE header field does not establish this credential classification. UAR also requires the verified issuer, subject and tenant to match the operator-owned trusted-host entry.

```yaml
security:
  trusted_host_principals:
    - issuer: https://issuer.example
      subject: kubo-service
      tenant_id: kubo-tenant
      host_id: kubo-host
```

An administrator registers/updates destinations with PUT /api/uar/mcp/servers/{name}, using the existing server configuration and grant_policy. Add allowed_agent_ids to the grant_policy:

```json
{"destination_id":"kubo-ipfs","trusted_hosts":["kubo-host"],"required_scopes":["ipfs"],"allow_private_http":true,"allowed_agent_ids":["persisted-kubo-agent"]}
```

Omitting allowed_agent_ids preserves existing compatibility. An empty list denies every agent. A singleton permits that persisted native agent only. Agent identity comes from the host's registered record, including revision; an inline artifact claiming the same ID is insufficient. Restrictions apply before initialization, discovery and invocation and remain effective when policy changes or a connection already exists. Direct loopback declarations sharing a restricted HTTP origin require a registered grant; a different name, path, query, fragment or equivalent loopback host cannot bypass that restriction. Separately registered destinations on that origin retain their administrator-managed grant policies.

The complete PUT body includes `name`, `enabled: true`, `transport: "remote_http"`, `url`, empty administrator `headers`, and the `grant_policy` object above. Use HTTPS for remote endpoints. `allow_private_http` permits deliberate local development at a loopback or literal private IP; it does not authorize arbitrary plaintext hostnames. Create the native agent through `POST /api/agents` before using its persisted ID in the policy.

Restricted destinations are catalog-only until a trusted host submits an explicit run grant through the existing mcp_servers field:

```json
{"mcp_servers":[{"name":"ipfs","grant":{"credential_revision":"operator-issued-revision","scopes":["ipfs"],"expires_at_unix":1900000000,"headers":{"Authorization":"Bearer <runtime-supplied-credential>"}}}]}
```

Use current expiration, revision and actual scope values. Secrets are supplied by the authenticated trusted host at request time. Registration is not execution authority and does not require a new credential store or environment secret. Set `server.mcp_shared_transports_enabled: false` to disable ambient sharing (default true; sidecar always disables it). With sharing disabled, global destinations likewise require explicit run grants. Resumed runs reattach matching resources and recheck current agent and destination restrictions. Different agents under the same principal cannot borrow an A-only grant.

## Remote skill upload
POST /api/uar/skills/import-content accepts JSON with one skill_markdown string containing the complete SKILL.md. Use authenticated administration as required by the existing skill API. The runtime validates the manifest and stores a user manifest skill only after checked durable persistence. Name collisions return conflict; upload never overwrites an existing skill. Normal GET /api/uar/skills/{skill_id} includes skill_markdown and artifact_digest (sha256:<hex>) for exact byte comparison. Bind it through the existing /api/uar/agents/{agent_id}/skills APIs. Content and binding survive restart. No shared client/server filesystem is required. Archive or supporting asset upload is outside this single-manifest contract.

## Complete AG-UI interrupt contract
Pinned @ag-ui/core 1.0.2, upstream commit 704b190e44aedda71a5388d2676370711c6b6b49. POST /api/uar/ag-ui/agents/{agent_id} emits SSE data containing standard events. An interruption ends a segment with RUN_FINISHED, threadId, runId, and outcome:{type:"interrupt",interrupts:[...]}.

Each tool approval interrupt contains id, reason:"tool_approval", message, toolCallId, expiresAt, and responseSchema. The schema is an object requiring approved:boolean with additionalProperties:false. Explicit true accepts; false denies. A cancelled resume status denies. String values such as "true" are invalid.

Each elicitation interrupt contains id, reason:"mcp_elicitation", message, expiresAt, responseSchema and metadata.uar:{serverName,request,resolvable}. The request is the exact MCP typed request: form mode includes message and requestedSchema; URL mode includes message, url and elicitationId. The response schema requires action, enumerated accept/decline/cancel, and includes content with the requestedSchema for form requests; additionalProperties is false. Accepted form content must validate against the requested schema. Decline/cancel and URL acceptance omit content. URL requests are untrusted links, never automatically fetched.

Resume uses the same threadId, a new runId, the preceding run's parentRunId, empty messages, and resume entries. Every pending interrupt must occur exactly once: missing, extra, duplicate or stale IDs reject the entire request. Each entry contains interruptId, status:"resolved" or "cancelled", and (when resolved) payload. Tool payload is {"approved":true} or {"approved":false}. Elicitation payload is {"action":"accept","content":{...}}, {"action":"decline"}, or {"action":"cancel"}. Cancelled elicitation status maps to action cancel. Resolvable:false means the connection is unavailable; an old elicitation ID cannot recreate a connection or replay a tool.

Resume cannot replace protected input/history/session/artifact identity. Current owner, workspace, expiration, resource restrictions and pending state are rechecked. Exact all-pending coverage includes both reasons in one segment. Multiple independent cold continuations cannot be partially resumed. Renewed permitted resources belong in forwardedProps.uar. Required tool approval remains mandatory with governance enabled or disabled.

## Acceptance and provenance
The bounded acceptance program must exercise both A2A transports and governance settings; zero invocation before approval, one after acceptance and zero after denial; protected-role task rejection and dynamic filtering; same-principal A/B and inline MCP isolation; both sharing modes and elicitation accept/decline; exact skill upload, binding, restart and persistence failure; default 300-second egress, loopback and no-model behavior; shipped authentication; discovery/version/CORS and effective-settings authorization/revisions. Every AG-UI event must validate against the pinned schemas. MCP execution sessions advertise form and URL elicitation; metadata discovery occurs before a run interaction channel exists and must not claim that capability. Acceptance correlates tool invocations to peer-issued MCP session IDs and requires the exact elicitation capability on every invoking session. Discovery-only sessions must perform no tool invocation.

Run product checks locally. GitHub Actions only builds and publishes deployment artifacts. Record local candidate provenance and published manifest/architecture digests. Pull and test the published digest without source patches before creating the final acceptance claim. If published acceptance fails, preserve the immutable tag and report failure.

### Default egress observation method
The local acceptance observer captures outgoing non-loopback frames with AF_PACKET for at least300 seconds before evaluating them, alongside interface counters. It requires zero capture drops and rejects all application traffic and unclassified frames. Only observed interface control traffic is excluded: gratuitous ARP requests (sender equals target), link-local multicast IPv6 neighbor discovery (types133,135,136 with hop limit255), and multicast-listener reports (type143 to ff02::16 with hop limit1). These frames appeared during OrbStack interface startup and made aggregate TX counts an invalid proxy for runtime calls. The receipt retains their classifications and counts. Type assignments follow https://www.iana.org/assignments/icmpv6-parameters/; capture semantics follow https://man7.org/linux/man-pages/man7/packet.7.html. The runtime remains under its default non-root user; a separate read-only capture process uses root inside the container network namespace. The launch-to-first-capture gap remains unobserved and is not certified.

### Reproduce installed-image acceptance

Complete all phase code, fixtures and documentation before invoking the program. Use the source at the published release commit, Docker with a Linux engine, Python 3, Node.js, initialized repository submodules and the repository's locked JavaScript dependencies. The schema loader uses the locked `zod` 3.25.76 package and verifies the published `@ag-ui/core` archive integrity; the A2A client loader verifies the pinned official grpcurl 1.9.4 archive. These client-side downloads do not alter the runtime image.

Set `UAR_RELEASE_IMAGE` to the immutable GHCR reference from the release and `UAR_RELEASE_EVIDENCE` to a new evidence directory. Run locally:

```bash
docker pull "$UAR_RELEASE_IMAGE"
python3 scripts/release/uar_1_1_acceptance.py \
  --image "$UAR_RELEASE_IMAGE" \
  --evidence "$UAR_RELEASE_EVIDENCE"
```

The program starts disposable persistence, provider, MCP peer and runtime processes. It records a final `receipt.json` even on failure, retains traces and redacted runtime logs, and removes its containers and network by default. A successful complete run records `result: "passed"` and `full_acceptance: true`. The optional `--gate` selector produces only a partial receipt and cannot establish release acceptance. `--local-tag` is restricted to candidate work; the published acceptance uses the digest reference.

The eight A2A cases cross JSON-RPC/gRPC, approval/denial and governance enabled/disabled. The synthetic governance-disabled runtime uses optional JWT on loopback because that is the runtime's permitted governance-disable posture; supplied credentials are still verified. Every shipped profile is separately required to reject anonymous calls. Dynamic activation is submitted, approved, continued and read back with the same role-limited credential. The pending approval must identify `activate_skill`, its actual provider tool-call arguments must identify the protected skill, and the native result must report that skill as ineligible without exposing its prompt or producing a peer effect.

Release evidence records the source commit, publication workflow run, multi-platform manifest digest, both architecture digests and the complete pulled-image receipt. The local arm64 candidate does not certify amd64 execution. Both architecture manifests must be present, and installed conformance is run on the locally executable architecture selected from the published manifest.
