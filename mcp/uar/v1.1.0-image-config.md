# UAR v1.1.0 image configuration and request shapes

Read-only notes from the UAR repository at tag `v1.1.0` (commit `d815ef72ac7d2c57a9bd18b23fcc58ffb224f326`), taken 2026-10-16 for `agent-backend-uar` 1.2 and 1.5. Sources: `Dockerfile`, `scripts/release/uar_1_1_acceptance.py` (UAR's own release acceptance program, which passed against the published digest), `scripts/release/uar_1_1_defaults.py`, `tests/fixtures/uar_1_1_mcp_contract.py`. These are the shapes the release was accepted with; where they differ from what `mcp/server/uar_provision.go` and `uar_proxy.go` inferred from `v1.1.0-kubo.md`, these win.

## Image

- Image: `ghcr.io/prometheus-ags/universal-agent-runtime@sha256:064f5004fb3ba76506abce5cf81285b2a8aa3e54fa5a22e2c2bfc97b1211e43b`.
- Command: `universal-agent-runtime --config <path>`; the acceptance program mounts its YAML read-only at `/opt/uar/release-config.yaml`.
- Ports: HTTP `1906`, gRPC `50051` (`EXPOSE 1906 50051`). Acceptance publishes them on `127.0.0.1:<random>`.
- User `65532:65532`, working directory `/opt/uar`, volume `/var/lib/uar`, `UAR_STATIC_DIR=/opt/uar/static`.
- Defaults (no config): authentication required, loopback bind, no model selected (`llm.provider_host: disabled`), memory embedding disabled.

## Configuration file (acceptance template)

```yaml
server:
  host: "0.0.0.0"
  port: 1906
  grpc_port: 50051
  cors_allowed_origins: []
  mcp_shared_transports_enabled: false   # or true
security:
  jwt_required: true
  jwt_secret: "<HS256 secret>"
  jwt_algorithm: HS256
  jwt_issuer: "<issuer>"
  jwt_audience: "<audience>"
  jwt_validate_nbf: true
  settings_admin_key: "<admin key>"
  skill_required_roles:
    <skill-id>: ["<role>"]
  trusted_host_principals:
    - issuer: "<issuer>"
      subject: "<host subject>"
      tenant_id: "<tenant>"
      host_id: "<host id>"
persistence:
  provider: surreal
  database_url: "http://surreal:8000"
  surreal_user: "<user>"
  surreal_pass: "<pass>"
  surreal_ns: "release"
  surreal_db: "<db>"
  vector_dimension: 384
  external_cache_enabled: false
memory:
  enabled: false
providers: []
native_tools:
  file_tools_enabled: false
  web_fetch_enabled: false
  terminal_exec_enabled: false
  session_search_enabled: false
```

Persistence: the acceptance runs a pinned SurrealDB companion container on a Docker network (`UAR_PERSISTENCE__PROVIDER=surreal`, `UAR_PERSISTENCE__DATABASE_URL=http://surreal:8000`, `UAR_REMOTE_SURREAL_DURABILITY_ATTESTED=1`). Environment variables with the `UAR_` prefix and `__` nesting override the file (for example `UAR_SECURITY__JWT_REQUIRED`).

## Model provider (liter-llm for kubo's 1.5 run)

Environment, as the acceptance sets it for its provider fixture:

- `LLM_BASE_URL` — OpenAI-compatible base URL (liter-llm), reached from the container (`--add-host host.docker.internal:host-gateway` for a host service).
- `LLM_MODEL` — model id.
- `LLM_API_KEY` — provider key.
- `LLM_PROTOCOL=chat` — not set by kubo's test yet; add it.

## Tokens

HS256 JWTs signed with `security.jwt_secret`. Claims: `sub`, `uar_credential_kind: "issuer"`, `roles` (array), `tenant_id`, `iss`, `aud`, `nbf`, `exp`, and for a trusted host `uar_instance_id` equal to the host id. The owner token used to create agents and import skills carries `roles: ["admin"]`; the host token carries `["admin", <role>]` and the host id. Admin and settings routes also send `X-UAR-Admin-Key: <settings_admin_key>` alongside `Authorization: Bearer <jwt>`.

## Request shapes used by the accepted release

- Create agent: `POST /api/agents`, expect `201`. Body: `version: "1.0.0"`, `kind: "agent"`, `id`, `metadata {title, description, tags}`, `runtime {entry: "agent", protocols: {}}`, `policy {provider {default {provider, model}, fallbacks: []}, tools {allow: [...], deny: [], max_concurrent, execution_mode: "direct"}, skills {prefer: [...], max_active}}`, `schemas {inputs, outputs, state}` (null each), `prompt {system, instructions: []}`, `memory {conversation {enabled}, kb {enabled, knowledge_bases: [], citation_required}}`, `tools {bundles: []}`, `ui {forms {enabled}, artifacts {enabled, preferred_types: []}}`, `extensions: {}`.
- Register an MCP server (host token): `PUT /api/uar/mcp/servers/<name>`, expect `200`. Body: `name`, `enabled`, `transport: "remote_http"`, `url`, `env: {}`, `headers: {}`, `sandboxed: false`, `grant_policy {destination_id, trusted_hosts: [<host id>], required_scopes: ["tools:invoke"], allow_private_http, allowed_agent_ids: [<agent id>]}`. Tool names surface to the agent as `<server>__<tool>`.
- Import a skill: `POST /api/uar/skills/import-content`, expect `201`, body `{"skill_markdown": "<SKILL.md text>"}`; the response's `skill_id` is derived from the manifest `name`.
- Bind skills: `PUT /api/uar/agents/<agent id>/skills`, expect `200`, body `{"skill_ids": [...]}`.
- Run grant (sent with each run): `{"name": "<server>", "grant": {"credential_revision": "v1", "scopes": ["tools:invoke"], "headers": {"Authorization": "<value>"}, "expires_at_unix": <unix>}}`. The AG-UI run and resume envelope that carries it is in `tests/fixtures/uar_1_1_mcp_contract.py` and `docs/AGUI_V1.md` at the tag.
- Governance: `GET`/`PUT /api/uar/settings/governance` with `expected_revisions`.

## For kubo

The correction cycle compares `uar_provision.go` and `uar_proxy.go` field by field with the shapes above and the fixture file, and `test/cli/mcp_uar_backend_test.go` gains: `LLM_PROTOCOL=chat`, the config mount at `/opt/uar/release-config.yaml` with `--config`, port `1906`, a SurrealDB companion (or the profile the defaults program uses), and JWTs minted from a test secret with the claims above.

## Found by the kubo real-service run (2026-10-16)

- `SKILL.md` frontmatter must carry `version` (`src/uar/domain/skills.rs:241-246`); import answers 400 `skill_markdown_invalid` ("missing field `version`") without it. Kubo adds `version: 1.0.0` when a skill lacks one.
- Registration order: `PUT /api/uar/mcp/servers/<name>` may happen before the agent exists, and must happen before the first run; a run that names an unregistered destination answers 422 `run_mcp_destination_unregistered`.
- A private-HTTP destination URL whose address is not RFC1918 answers 422 `run_mcp_destination_invalid`.
