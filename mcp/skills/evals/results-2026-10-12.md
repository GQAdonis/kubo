## Reading the result

- Near-misses: 6/6 clean. No `ipfs:` skill fired for the SHA-256, Merkle tree, S3, tweet pin, Docker GC or Python pin prompts.
- Positives: 5/22 (23%). The spec names no pass threshold, so 1.4 stays open rather than being ticked on a number we chose after seeing it.
- Why positives miss, from the per-prompt tool list: in 13 of 17 misses the model went straight to tools with no skill (the other 4 answered in text), either with the plugin's MCP tools directly (`ipfs_cat`, `ipns_resolve`, `pin_ls`, `pin_verify`, `repo_stat`) or with the `ipfs` CLI through Bash. Claude Code consults a skill mainly for tasks it cannot do directly, so single-call requests ("what does /ipns/x resolve to", "read this CID") do not need one. The misses on publish, retrieve and DAG/CAR are mostly of this kind.
- Confounds that depress the rate: many prompts refer to material that is not supplied ("these meeting notes", "this json config"), so the model asks for it or inspects the empty working directory instead of reaching for a skill; `--max-turns 2`; this machine has several hundred other skills competing; the CLI is reachable through Bash. One run per prompt, so a single flip changes a skill's row.
- Not a description-length or validity problem: all 8 descriptions pass `skills-ref` and already name their tools and trigger phrases. No description was changed in this pass.

## Proposed next steps (not applied)

If skills must fire for every single-tool request, descriptions cannot get there alone; if they only need to fire for multi-step or confirmation-bearing workflows, restrict the positives to those (publish with pin and provide choices, `pin_rm` and `repo_gc` flows, IPNS key plus publish plus TTL, MFS edit then publish, CAR export and import, troubleshooting a missing tool or hung CID).
2. Re-run with realistic payloads in the prompt (actual text, a real CID) and `--disallowedTools Bash`, so the only routes are a skill or the MCP tools. This separates "skill ignored" from "CLI used instead".
3. If descriptions are tuned, lead each with the user's intent in plain words before the tool names, for example for `ipfs-pin-management`: "Keep content on your IPFS node, check what is kept, or free disk space safely. ..." and for `ipfs-retrieve-verify`: "Read, list or verify content by CID or ipfs:// path. ...". Re-run only the changed skill's three prompts (about 3 runs each).
