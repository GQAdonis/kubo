## Failures to report (no code changed)

1. Startup with an unreachable remote store. Config `cfg-ui-embeddings-unreachable.json` (remote SurrealDB `http://127.0.0.1:59998`, embedder `http://127.0.0.1:59997/v1`, remote extractor `http://127.0.0.1:59996`; nothing listens). Result: `Error: ipfs mcp: embeddings: embeddings store: define schema: surrealdb request: dial tcp 127.0.0.1:59998: connect: connection refused`, exit 1. The plan revision 4 amendment (ADR-0009 absent-dependency rule) expects the server to start and `/index/status` to report the stages unavailable. The status check was therefore never reachable. Only the remote-store path was exercised; embedded mode was not tried.
2. `/agui` with no valid principal. The task-1.3 wording expects 503 `backend_not_configured` with the principal tokens absent. The handler (`mcp/server/agui.go`, ServeHTTP) returns 403 `permission_denied` unless a `ui` principal authenticated, and only then reports 503. The 503 was reproduced with a throwaway `ui` token created inside the container. Either the acceptance text or the anonymous-loopback behavior needs an architect decision.

## Notes and deviations

- Every container used its own `IPFS_PATH=/tmp/ipfs-smoke`, `--offline`, swarm 4101, API 5101, gateway 8181, `ipfs mcp` 5151, all bound to 127.0.0.1 inside the container. Only `127.0.0.1:5151:5151` was published; because the listener is loopback inside the container the published port is not reachable from the host, so probes ran with `docker exec` (busybox `wget`/`nc`): `probe.sh`, `raw.sh`, `tools.sh`. Ports 4001, 5001, 8080, 5050 were never used. Busybox `wget` does not show error bodies, hence `raw.sh`.
- Throwaway tokens were generated by `smoke-entry.sh` inside the container (`GEN_TOKEN=1`), held only in `/tmp/ui.token` in that container, never printed, and gone with the container.
- Scenarios: a = no config; b = `cfg-ui.json` with credential env unset; c = `cfg-ui.json` with token; d = `cfg-ui-embeddings-unreachable.json` with token.
- Containers started (all stopped and removed by ID, `container-ids.txt`): a `a0f43d4d...`, b `72fa6c91...`, c `5beb77cc...`, d `93a6bce4...`. No images or volumes pruned.
- `go test ./mcp/...` was a mix of cached and fresh runs; `mcp/server` ran fresh (105s).
