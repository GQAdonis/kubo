## 4. Metrics scraping

The ipfs pod template carries `prometheus.io/scrape: "true"`, `prometheus.io/port: "5001"` and `prometheus.io/path: /debug/metrics/prometheus`. These annotations came over from the original GKE deployment. Nothing in this cluster reads them:

- no Prometheus, VictoriaMetrics, vmagent, Grafana Agent or Alloy, OpenTelemetry Collector, Datadog, New Relic, Fluent, Vector, Telegraf or SigNoz pod in any namespace. Every image matching `prom` is a `ghcr.io/prometheus-ags/...` application image;
- no monitoring CRDs (`ServiceMonitor`, `PodMonitor`, `VMServiceScrape`, `OpenTelemetryCollector`);
- `kube-system/metrics-server` v0.9.0 reads kubelets only (`--kubelet-preferred-address-types=InternalIP,...`), never pod ports.

So no scraper is a consumer. A scraper added later needs its own allow rule on 5001.

## 6. CNI and existing policy

- The CNI is Calico: DaemonSet `kube-system/calico-node` (2/2), plus `calico-kube-controllers` and `calico-typha`, with `crd.projectcalico.org` CRDs. kube-proxy runs alongside it. FelixConfiguration `default` has `ipipEnabled: true`.
- There are three LKE-managed GlobalNetworkPolicies: `allowbgp`, `default-allow` (order 1000) and `lke-localhost-healthchecks`. All three select `has(lke.linode.com/pool-id)`, a node label. The cluster has zero HostEndpoints, so these policies apply to no pod and do not override Kubernetes NetworkPolicy on pods.
- Kubernetes NetworkPolicies already exist in `argocd` (7, Helm chart), `knowme` (3) and `onyx` (1). None exist in `ipfs`, `flint-core` or `envoy-gateway-system`.
- Enforcement is not verified. `knowme/uar` has `httpGet` probes behind a restrictive policy and is Ready. That fits Calico allowing node-to-local-pod probe traffic, but no enforcement at all would look the same. Task 5.4 is the proof.

## 8. Same-pod traffic and probes on the ipfs pod

- The `ipfs-mcp` sidecar runs `ipfs mcp --api=/ip4/127.0.0.1/tcp/5001` (StatefulSet `ipfs`), so it reaches kubo over loopback inside the pod. NetworkPolicy does not apply to that path.
- The `postStart` hook uses `--api=/ip4/127.0.0.1/tcp/5001` too.
- Probes: container `ipfs` has an exec liveness probe (`ipfs id`) and an exec readiness probe (`ipfs version`), both against 127.0.0.1:5001. Container `ipfs-mcp` has no probes. No kubelet network probe touches 5001, 5050 or 8080.
