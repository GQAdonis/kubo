# mcp/server

Go package `github.com/ipfs/kubo/mcp/server`: the IPFS MCP server behind `ipfs mcp`. It lives in the root module (no nested `go.mod`) and is wired from `cmd/ipfs/kubo/mcp*.go`. Decisions: [ADR-0001](../../docs/mcp/0001-mcp-server-placement.md) and [ADR-0003](../../docs/mcp/0003-confirmation-and-auth.md).

## Rules

- The server is a client of a running Kubo daemon. It reaches it only through `client/rpc` (`/api/v0`). It never opens the repo or takes `repo.lock`, imports no `core/` internals and has no offline mode.
- Tools, schemas, annotations and the default selection come from the embedded [`mcp/contract`](../contract). `New` fails when a registered tool has no catalog entry.
- On stdio, stdout carries only JSON-RPC. Logs go to stderr.
- Tool failures are results with `isError: true` and a contract `ToolError` in `structuredContent`. Successes carry `structuredContent` plus the same JSON as a text block.

## Daemon discovery

`--api` (multiaddr or http(s) URL), then `$IPFS_PATH/api`, then `~/.ipfs/api`. `--api-auth` takes the same secret form as the rest of the CLI (`bearer:token`, `basic:user:pass`). The daemon must be at least the contract's `minKuboVersion` (0.29.0); pre-release suffixes are ignored. Tools whose RPC commands the daemon does not list are omitted and reported by `ipfs_node_status`. If the daemon refuses `commands`, every tool is kept. **Startup wait.** A daemon that is not reachable yet (connection refused, or no `api` file when `--api` is not given; the file is read again on each attempt), as when `ipfs mcp` runs as a sidecar that starts before the daemon container, is retried with a 1 s to 5 s backoff for `daemon.wait` (default `60s` with `--http`, none for plain stdio; an explicit value is always honored; `0s` fails at once; at most `10m`), logging the first retry at Warn and each later one at Info, then fails with the usual `cannot use the ipfs daemon API` error. Userinfo in an `--api` URL is removed from those lines and errors. A refusal by the daemon (an `API.Authorizations` 403) or an unsupported version fails at once. 

## Tool selection

`--tools` takes group names and the selector `destructive`. Default: every group in the contract, without destructive tools. Naming only `destructive` adds destructive tools to the default groups. `--read-only` keeps class `none`.

## Streamable HTTP and authentication

`ipfs mcp --http` serves MCP over HTTP instead of stdio. It is off by default; with it off no TCP listener is opened.

| Setting | Default | Override | Off switch |
| --- | --- | --- | --- |
| listen address | `127.0.0.1:5050` | `--http=<addr>`, `IPFS_MCP_HTTP_LISTEN`, config `http.listen` | omit `--http` |
| allowed browser origins | none (all cross-origin requests get 403) | config `http.allowed_origins` | leave empty |
| body limit | 4 MiB | config `http.max_body_bytes` | always enforced |
| idle session timeout | 30m | config `http.session_timeout` | always enforced |

- **Addresses.** `host:port` or a `/ip4|/ip6|/dns*/<host>/tcp/<port>` multiaddr. The ports of other local services (4000, 4001, 5001, 8080, 1906-1908, 50051, 8181, 8081, 11434, 23001, 28000; the list in `listen.go` is checked against the contract schema) are rejected. A non-loopback address is refused unless a verifier is configured. Tests bind port 0.
- **Requests.** Every route passes the same chain: Host must be loopback on a loopback listener (DNS rebinding, 403), an `Origin` must be the listener itself or allowlisted (403), cross-site browser fetches are refused unless the origin is allowlisted, the body is capped, and the bearer token is verified (401 without one). TLS is left to a reverse proxy.
- **`AuthVerifier`** (`auth.go`) returns an `Identity` and an expiry; `TokenVerifier` adapts it to the SDK's `auth.TokenVerifier` and puts the identity in `TokenInfo.Extra` (and its ID in `UserID`, so the SDK refuses another principal's use of a session). A verifier may also return RFC 9728 protected-resource metadata; the server then serves it at `/.well-known/oauth-protected-resource` and advertises it in 401 responses. The static verifier has none. An Ory Hydra verifier is a second implementation of this interface; no route or tool handler changes.
- **Static bearer tokens** come from an environment variable or an absolute file path (`SecretRef`), are kept as SHA-256 digests and compared in constant time against every credential. They are never literals: not on the command line, and not in the config file (the schema rejects them, and error messages redact them). `--auth-token-env NAME` / `--auth-token-file PATH` define the operator principal (read every group, write every group; destructive only if `destructive` is in `--tools`). `--mcp-config FILE` (or `IPFS_MCP_CONFIG`; the flag wins; the root `--config`, which names the Kubo repo config, is not read) defines named principals validated against `mcp/contract/config`.
- **Principals** are read-only until a group is granted by name: `groups` (read-class tools, default `["*"]`), `write_groups` and `destructive_groups` (both default empty). Scopes follow: `ipfs:read`, `ipfs:write`, `ipfs:admin`. `tools/list` shows only what the principal may call and a call outside its grants is `permission_denied` before any handler runs. A grant of `destructive_groups` makes the server register destructive tools; without one they stay off. With no principal and no operator token at all, a loopback listener serves the read-only tools to an anonymous principal.
- **Confirmation** works as on stdio. The session ID is the MCP session, so a confirm token from one HTTP session is refused in another and for another principal.
- **Routes.** `/mcp` is served here. `HTTPServer.Mount` (the `RouteMounter` interface) adds more behind the same chain; later changes register with `RegisterRouteProvider` for `/agui`, `/a2a` and the public `/.well-known/agent-card.json`. Principal kinds are scoped per route (`human-mcp`, `ui`, `uar` on `/mcp`; `ui` on `/agui`; `a2a` on `/a2a`), so one protocol's token does not open another's route. The `admin` kind (ADR-0009) is in no route's default: it opens only the settings route, which mounts with an explicit kind list, and its token is refused on `/mcp`, `/agui` and `/a2a`. The settings subtree also serves `POST /agent/settings/test-connection` and `GET /agent/settings/models` (mcp-agent-settings-api 1.4): both probe only a candidate URL — https, or http on loopback, never credentials in the URL — under a 10-second bound, persisting nothing, and a failed model list answers in the probe's `{ok, detail}` shape because the closed error-code set has no "backend unreachable" code. The stored key is attached only when the candidate's host and port equal the current backend's (ADR-0012); an acknowledged host and the `local` sentinel do not qualify, and a PUT that moves the backend scheme, host or port without `api_key` clears a key stored through the API and answers with `key_not_carried`; any other host is probed without `Authorization`, the answer carries `key_sent: false`, and a 401 or 403 from it is reported as reachable with the key withheld (`ok: true` on test-connection; `ok: false` with the same detail on the model list, whose success shape has no such field). `GET /agent/settings/events` (mcp-agent-settings-api 1.5) is the change stream: one SSE event per applied write carrying only the new revision (contract `settings/settings-event.schema.json`), with the current revision as the first event so a change between a client's last read and the subscribe is not missed; subscribers re-read the settings route for the state, so no event can carry settings values or key material.
- **`ipfs mcp --print-rpc-allowed-paths`** prints an `API.Authorizations` entry whose `AllowedPaths` are the full RPC paths (from the contract's `rpc` lists, plus `version` and `commands`) of the tools selected by `--tools`, `--read-only` and config `tools.disabled`. Kubo matches `AllowedPaths` by string prefix, so a shorter path grants more than it appears to. Use the entry's secret with `--api-auth`.

## Confirmation gate

Every tool of class `write` or `destructive` passes the gate in `registry.go` before its handler runs (ADR-0003). Nothing runs silently, on any transport.

1. **Elicitation.** If the client advertised it, the first handler call returns an input-required result (SEP-2322 multi round trip) holding the elicitation request, and a signed request state. The SDK obtains the answer and calls the handler again. Only `accept` with `confirm: true` runs the call. Works on every protocol version.
2. **External resolution.** For a client that cannot elicit, the call becomes a pending confirmation in the `Broker` (pending, then approved, denied or expired; approved then executed exactly once). `Options.Resolvers` are the human-presence mechanisms (`Resolver` interface) that call back with the decision; later changes add the native prompt, the Desktop window and the AG-UI interrupt. The result is `confirmation_required` with the confirmation ID, summary and resolver names. A repeat of the identical call from the same session and principal reports `confirmation_pending` and never approves; once approved it runs exactly once.
3. **No resolver.** The call is refused with `confirmation_unavailable`.

Two signed handles exist, and they are kept apart (domain separation):

| Handle | Used for | Accepted when |
| --- | --- | --- |
| `confirm_token` (`use: confirm_token`) | the repeat call after external resolution | the confirmation was opened by the `external` mechanism and is already `approved` |
| `requestState` (`use: request_state`) | the elicitation retry (`InputRetry`) | the session advertised elicitation, the confirmation was opened by the `elicitation` mechanism and is still `pending`, and the answer is `accept` with `confirm: true` |

Both are HMAC-SHA256 over session, principal, tool, canonical arguments (RFC 8785), expiry and a single-use nonce, 120 seconds. Each use has its own key (derived from one per-process random key) and its claims carry a `use` field the verifier checks, so a confirm token is never a request state and a request state is never a confirm token: a session that holds a confirm token cannot present it as a request state next to a forged `inputResponses` answer to approve its own call. Neither handle is consent. The confirm token is issued only to principals that can use it (not `a2a` or `uar`); pending, denied, expired and executed confirmations reject it. Each pending confirmation records the mechanism that opened it, and `Broker.Resolve` refuses the `elicitation` resolver for a confirmation opened any other way. Principals reach the gate through `WithPrincipal`; stdio runs as `LocalPrincipal`.

A destructive call from the `ui` principal sets `requires_native_prompt` in `ConfirmationRequired`; `agui-interrupt` is then not listed in `resolvers` (the chat may deny, never approve). With no other resolver configured the call is refused with `confirmation_unavailable`.

Prepared confirmations also carry `effect_digest`, computed by the existing canonicalizer over `{arguments, tool}` with only top-level `confirm_token` removed. Optional `destination` names a known configured effect target without exposing a credentialed endpoint. The v1 token's args-only hash and acceptance rules remain unchanged. The shared gate checks retained effect and daemon endpoint bindings before consuming approval; `executed` records that single-use claim before invocation and does not mean the operation succeeded.

Upgraded resolvers may echo the displayed digest using the [confirmation contract's transport fields](../contract/confirmation/README.md#reviewed-effect-wire-placement-amendment-c11-2026-10-20). Both MCP answer-level and call-level echoes must validate and agree. Malformed explicit metadata is refused; an authorized digest mismatch is non-retryable `confirmation_digest_mismatch` and consumes nothing. Legacy clients may omit the echo while retaining every original binding and gate check. `resolved_by` records the actual elicitation/native/Desktop/CLI/chat resolver; pending requests, automatic expiry and system withdrawals never invent a human resolver. UAR's synthetic approvals remain separate: without a trusted retained effect digest, an explicit echo is refused before anything is forwarded to UAR.

`execution.go` keeps the winning invocation's separate `not_started -> running -> succeeded | failed | unknown` record. The shared handler stores successful evidence before decorating or serializing its response, so a delivery error cannot erase a successful node operation. Receipts bind the decision, canonical tool and effect digest; references come only from typed returned identifiers. Bulk indexing start/resume receipts say `job_accepted`, without promising eventual job completion. Definite reported failures have bounded public error messages; ambiguous network/deadline/cancellation, partial stream results and read-back failures after mutation remain unknown. No outcome lookup or handler automatically retries a write.

The winning invocation's result carries the detached authoritative snapshot in `_meta["ipfs-mcp"]` as `{confirmation_id, effect_digest, execution}`, including `execution.receipt` only after success. Content, structured output, error status and unrelated metadata retain their existing meanings. External MCP Apps receive this through the standard tool-result notification without HTTP decision credentials. An invalid/replayed/losing claim receives no other invocation's snapshot; UAR's synthetic backend prose never produces this node-operation envelope.

Broker snapshots retain `resolved_surface` separately from `resolved_by`. Trusted adapters identify MCP host, Desktop, native prompt and CLI without exposing session handles; the owned AG-UI resume accepts only a validated `forwardedProps.ipfs.surface` chat/inbox pane hint. That hint supplies no mechanism, identity, presence factor or approval right. Missing pane attribution remains optional. Real terminal execution evidence always stays alongside attribution and takes precedence over any client “answered elsewhere” presentation; a stale response cannot replace it. Expiry or withdrawal may preserve a real earlier approver as historical provenance, but never invent a new human resolver for the automatic transition. UAR backend approvals keep a distinct source kind and never merge into node confirmations.

Decision history uses the broker's single retained store, separate from expiring token records: at most 200 resolved observations total per server for seven days. It includes denials, expiry, withdrawals and terminal execution evidence, with in-flight claims kept until their handler settles. Eviction clears the token record's snapshot reference as well, so token grace cannot retain a second history or resurrect evicted evidence. Owner-filtered snapshots use the full private identity binding captured before scrubbing the stored principal; a scrubbed display principal never reconstructs ownership. Process-local epoch and history start reset on restart. Revisions are opaque equality-only HMAC tokens over that owner's visible IDs and mutation versions, with no numeric or ordering guarantee; another identity's activity affects them only through actual eviction of owned history. These internal source snapshot hooks are the reuse point for later authenticated read routes and event adapters. Tool contexts remain bounded by the existing 60-second timeout; implementations must honor cancellation. Abnormal handler exits record unknown through a defer. Process loss clears in-memory evidence and authorization; it cannot resume or replay a consumed write. Returned snapshots copy the execution/receipt data and retained owner bindings remain private.

Destructive tools (`pin_update`, `pin_rm`, `mfs_rm`, `key_rm`, `repo_gc`) are registered only when `destructive` is named in `--tools`; once enabled they are still confirmed. `ipfs_node_status` reports one left out as `destructive_disabled` (precedence: `read_only`, `group_disabled`, `destructive_disabled`).

## Principal enforcement, egress and check-uar

Change `mcp-agent-principal-enforcement` (ADR-0004). It lives in `ipfs mcp` only: no daemon, `config/` or `/api/v0` change, and nothing is contacted unless the config names it.

| Piece | File | Behavior | Off switch |
| --- | --- | --- | --- |
| Configured principals | `config.go`, `principals.go`, `access.go` | Kinds `human-mcp`, `ui`, `a2a`, `uar`, `admin`; read-only until groups are granted by name (the tool-group keys grant an `admin` principal nothing). A token that maps to no principal is 401. The name `operator` is reserved; `uar` needs a `uar` block; `check: assert` is valid only for `uar`. An absent credential (unset variable, missing or empty file) disables only that principal with a startup warning (CRITICAL-2); the principal authenticates nothing until the reference resolves. If principals are configured and none resolves, with no `--auth-token-*` operator token, HTTP startup fails naming each principal and its expected variable or file (never a value) instead of serving the anonymous listener (S5); in a pod, where loopback is every container, this keeps a missing Secret from silently dropping authentication. | Remove the principal or its credential. |
| Egress acknowledgement | `egress.go` | A configured principal needs `egress_ack` for every `contentEgress` tool; an empty list refuses with `egress_not_acknowledged` (`details.reason`: `no_egress_ack`). For `ui` and `a2a` the hosts of the `llm`, `embeddings.embedder` and `embeddings.remote` sections must also be covered (`backend_host_not_acknowledged`, `details.missing_hosts`). `"local"` covers loopback hosts only; a named host covers any port unless the entry has one. The refusal comes before argument validation and before any daemon call. | An `egress_ack` that names the hosts. |
| Settings-write egress extension (D4) | `settings.go`, `settings_overlay.go`, `egress.go` | A settings write that moves the effective model backend to a host the calling `admin` principal's `egress_ack` (configured list plus previously confirmed extensions) does not cover is refused 409 `egress_confirmation_required` (`details.host` names it) unless it carries `egress_confirmation` naming exactly that host; the write then extends that principal's `egress_ack` with the newly chosen host only, persisted in the overlay's `egress_ack` map. A confirmation naming any other host, or arriving when no host changes, is refused the same way. | An `egress_ack` that already names the host: no confirmation is asked. |
| `check-uar` | `uarcheck.go`, `policy.go` | See below. | No `uar` block: no connection. |
| Shell-capable refusal | `policy.go` | With the `cli` resolver on, every HTTP identity with write or destructive grants needs `shell_capable: false`; otherwise those grants are withdrawn (`permission_denied`, `details.reason` `shell_capable_unasserted`). The `--auth-token-*` operator identity has no such assertion and no exemption, so it loses writes under `--confirm=cli` too; the refusal and the startup message name the supported path, a `human-mcp` principal with `write_groups` and `shell_capable: false`. Stdio is untouched. | `--confirm` without `cli`. |
| Stdio guard | `egress.go` | A session whose MCP `clientInfo` name or title says UAR (word `uar`, or `universal agent runtime`) and is not a configured `uar` principal is refused `contentEgress` tools (`details.reason` `client_identifies_as_uar`). `clientInfo` is self-reported: a misconfiguration guard, not a security boundary. | None; use a configured `uar` principal. |

`requires_native_prompt` is satisfied only by presence resolvers (`gate.go`, `IsPresenceResolver`); `cli` never satisfies it.

**check-uar.** `Server` runs `UARChecker` for each `uar` principal at startup (printed to stderr), at every session `initialize` (always fresh) and, for open sessions, once the verdict is older than the contract's `recheckInterval` (`mcp/contract/agentic/uar-preflight.json`, 30 seconds). The same engine backs `ipfs mcp check-uar [<url>] [--principal NAME]`, which exits non-zero unless the verdict is `ok`. It contacts only the card URL the operator passes or configures and the settings path pinned in `uar-preflight.json` under the same base; redirects and proxies are not followed. The minimum version, settings path and recheck interval are read through `contract.LoadUARPreflight()`; the server holds no copy (ADR-0007). Tests inject a path with `WithSettingsPath`, never as a default. A settings response is validated against `agentic/uar-effective-settings.schema.json`; one that does not validate (including the per-key record array UAR serves today) is unreadable. Findings:

- `refuse` disables that principal only (initialize fails with a JSON-RPC error, an open session gets `permission_denied` with `details.reason` `uar_check_failed`): the card is unreadable, the version is not a published release (`x.y.z` only, no pre-release or build suffix), is below the minimum (`uar.min_version`, else the contract's `minVersion`; with neither set the check refuses `min_version_not_set`), an unauthenticated settings request is not 401/403, a chat model or embedder is remote (not `local`, `disabled` or loopback) and not in `egress_ack`, or the settings are unreadable and the principal is not `check: assert`. While the contract's `settingsPath` is `null` nothing is read or probed: `check: verify` refuses with `settings_unreadable` and `auth_probe_inconclusive`; `check: assert` reports both as info and the version check still runs.
- `read_only` withdraws write and destructive grants: governance not enabled, `terminal_exec` enabled or a non-empty `native_tools.shell_tools`, any MCP server besides this `ipfs mcp` (`/mcp` on its bound address), or the tool inventory not exposed by the settings API.
- `check: assert` waives only what the settings API does not expose (and prints the assertion at startup for each `uar` principal); whatever it returns is still verified. It never waives the card, version or auth probe.
- The admin credential comes from the env var or file named in `uar.admin_credential`, is sent as the `X-UAR-Admin-Key` header (not a bearer) only over https or to a loopback host, and is never printed or logged.

The verdicts promised in `mcp/contract/fixtures/uar/README.md` are asserted in `uarsettings_test.go`; the fixtures in `testdata/uar/` are synthetic. A different shape reads as unreadable settings and fails closed. The admin credential is `Authorization: Bearer`, which is the CONFORMANCE item 8 acceptance check, not what UAR serves today (`x-uar-admin-key`).

**MCP App views.** `tools.app_views` (default `true`; `--no-app-views`) false registers no `ui://` resource and puts no `_meta.ui` on any tool; tools are otherwise unchanged. With views on, a view is served only while at least one of its linked tools is registered.

## Agent backend and tool loop

Change `mcp-llm-proxy-loop` (ADR-0004, tasks 1.1 to 1.6). Everything here is compiled out by the `noagent` build tag (`make build GOTAGS=noagent`) and by `nomcp`; in a `noagent` build the `--llm-*` flags do not exist and an `llm` section in `--mcp-config` is refused.

| Piece | File | Behavior | Off switch |
| --- | --- | --- | --- |
| Backend configuration | `agent_settings.go`, `principals.go` | `--llm-base-url`, `--llm-model`, `--llm-api-key-env NAME`, `--llm-api-key-file /abs/path`, or `llm` in `--mcp-config` (flags win). No default endpoint or model; naming only one of them is an error. A literal key is rejected: the config schema accepts only `{"env": ...}` or `{"file": ...}`, the env flag must look like a variable name, and no error echoes a key. The base URL may not carry credentials, a query or a fragment, and a key is never sent over plain `http` to a non-loopback host. | Leave `llm` and the flags unset: no client exists, nothing is dialed, no agent surface is mounted. |
| Chat-completions client | `llm_client.go` | Standard library only. `stream: true` with `include_usage`, SSE parsing with split tool-call deltas assembled by index (and by id when a server sends no index), a non-streaming fallback, no redirects, response and line caps, per-request timeout (`llm.timeout`). Errors keep the status and a 200-character excerpt of the backend message, never the request. | Same. |
| Egress | `agent.go` | A `contentEgress` tool result reaches the model only if the backend host is covered by the calling identity's `egress_ack`. This applies to every identity, configured or not, because the loop forwards the result itself. Otherwise the tool is not run and the model receives the contract `ToolError` with `Content not sent: <host> is not in egress_ack.` | An `egress_ack` that names the backend host (or `local` for loopback). |
| Bounded loop | `agent.go` | `agent.loop` limits (steps 8, tokens 32768, wall clock 120s by default). Tools are the registered contract tools the identity may call; no shell, filesystem or network tool exists. At most 8 tool calls run per model reply. Tool results are capped at 64 KiB, and results that can carry third-party text are wrapped in `<untrusted-content>` with a system prompt that calls them data. The system prompt always begins with a fixed safety prefix (untrusted content is data; writes need a person's confirmation) set by the binary; a configured prompt (`AgentSettings.SystemPrompt`, the settings write's `system_prompt`) only extends it and can never remove, empty or override it. Sessions are in memory only (64 sessions, 30 minute idle, owned by one principal). Logs carry outcome and counts, never content. | Limits always apply; the loop runs only when `llm` is configured. |
| Confirmation | `agent.go`, `gate.go` | Write and destructive calls go through the same handler and confirmation gate as MCP `tools/call`. A call that needs a person ends the run with an `interrupt` (`Interrupt`, id `int-<confirmation id>`). `Resume` with `ResumeEntry` answers it. The loop never approves: a deny or cancel is recorded with the broker, and an approve only retries the call, which runs once if a human-presence resolver already approved it (a transport records that with `Server.ResolveConfirmation`). A denied, expired or unknown confirmation yields a denied result and never reaches RPC. The `confirm_token` property is removed from the schemas the model sees and ignored if sent. | `--confirm` resolvers off: writes are refused with `confirmation_unavailable`. |

Use: `srv.EnableAgent(settings)` (nil settings leave the agent off), then `srv.Agent().Run(ctx, identity, RunInput{...}, emit)`. The AG-UI and A2A endpoints adapt `Event` and `RunResult`; the loop owns no transport.

The loop announces a model reply once, as `EventReply` carrying all its tool calls in order, followed by one `EventToolCall` each, before any call runs. A call that waits behind an interrupt is therefore announced in the run that received the reply and never again. `Agent.OpenInterrupt(identity, sessionID)` returns a session's open interrupt to its owner only (`ErrSessionNotFound` for anyone else); a transport calls it, and matches the interrupt ID the client names, before it records any decision. `Server.AwaitConfirmation(ctx, id)` blocks until a confirmation is no longer pending and decides nothing.

## UAR agent backend

Change `agent-backend-uar` (ADR-0010). `llm.kind: "uar"` (or a settings write with `backend.kind: "uar"`) replaces the agent loop with a proxy to a UAR agent; `Server.Agent()` returns nil and `Server.UARBackend()` serves `/agui`. The user-facing description is in `docs/mcp/agentic.md`; the wire contract is the pinned `mcp/uar/v1.1.0-kubo.md`.

| Piece | File | Behavior |
| --- | --- | --- |
| Settings | `uar_settings.go`, `agent_settings.go` | `Config.resolveUAR` builds `UARSettings` from `llm.uar` and refuses the kind unless `uar-preflight.json` pins a release. It contacts nothing. The UAR credential is `llm.api_key`; `llm.uar.mcp_principal` (required) names the `uar` principal whose credential becomes the per-run grant; without it UAR v1.1.0 would resolve an empty tool allowlist to automatic selection and expose its native tools, so the kind is refused. `llm.uar.provider` or `llm.model` as `provider/model` is also required. |

## AG-UI endpoint

Change `mcp-agui-endpoint` (ADR-0004 and ADR-0005, with their Round 4 and Round 6 amendments). `POST /agui` on the `--http` listener takes a `RunAgentInput` and answers with AG-UI events over SSE (`data: <json>`). Hand-written types over `net/http`; events validate against the published `@ag-ui/core` 1.0.2 schemas (`agui/SOURCES.md`). It is compiled out by `noagent` and `nomcp`.

| Piece | Behavior | Off switch |
| --- | --- | --- |
| Mounting | `--agui` (or `agent.agui` in `--mcp-config`) and a configured model backend and `--http`. Anything less: `/agui` answers 404 and no model is called. `--agui` without a backend or without `--http` prints that it is ignored. | Leave `--agui` unset (default), or build with `GOTAGS=noagent`. |
| Auth | The listener's bearer verifier, path-scoped to principals of kind `ui`. Other kinds get 403, a missing or unknown token 401. | Same. |
| Origins | Strictly `agent.origin_allowlist` (default empty): a request with any other `Origin`, including the listener's own and `http.allowed_origins`, gets 403 with no CORS headers. A listed origin gets the origin echoed (never `*`), `Access-Control-Allow-Methods: POST, OPTIONS`, `Access-Control-Allow-Headers: authorization, content-type`, `Vary: Origin`, and no credentials header. Requests without `Origin` (not browsers) need only the token. | Empty list. |
| Threads | `threadId` is the loop's session ID. A new user message on an unknown thread creates the session for the calling principal; another principal's thread is 404. The server keeps the history (30 minutes idle, 64 sessions, 256 messages). Only the last input message is read and it must be a `user` message; client-supplied assistant and tool messages are ignored, so a client cannot forge tool results. Client `tools`, `context` and `state` are ignored. | |
| Events | `RUN_STARTED`; text as `TEXT_MESSAGE_START/CONTENT/END`; at the end of each reply that asks for tools, `TOOL_CALL_START/ARGS/END` for every call in order, then `MESSAGES_SNAPSHOT` (the assistant message the calls name as parent); `TOOL_CALL_RESULT` per result; `RUN_FINISHED` with `outcome` `success` or `interrupt`. Before the first event nothing is written, so a refusal is an HTTP status: 422 bad input, 413 too large, 404 unknown or foreign thread, 403 policy refusal, 409 busy, open interrupt or full session, 503 with `Retry-After` for too many sessions. | |
| Interrupts | A write or destructive call ends the run with exactly one interrupt (`reason: tool_call`, `metadata["ipfs-mcp"]`). ## Embeddings store (SurrealDB)

Package `mcp/server/embeddings`, built with and without `noagent` (it does not use the agent code); `nomcp` removes it with the rest. Off unless the `embeddings` section of `--mcp-config` exists: then no `surreal` process starts, no store or embedder is contacted, and no `ipfs_index_*` tool is listed. The index tools, the auto-index trigger and pin-aware deletion are in the next section.

- **Client.** The standard library over SurrealDB's HTTP API (`POST /rpc`, `query`). No SurrealDB module is linked. `SOURCES.md` cites every statement.
- **Schema.** Table `ipfs_chunk` (`cid`, `path`, `mime`, `chunk_index`, `model`, `dims`, `vector`), an index on `cid`, and an HNSW cosine index of the configured dimension. The chunk text is not stored. A database whose index has another dimension is refused (`ErrDimensionMismatch`).
- **Embedded mode** (`mode: embedded`). `ipfs mcp` runs `surreal start --bind 127.0.0.1:<ephemeral> surrealkv://<data_dir>/db` from `embedded.surreal_binary`, an absolute path that is never looked up on `PATH` and never downloaded, after a `surreal version` check against `embedded.min_version` (default 3.0.0). The port is chosen by the OS and never one of the reserved ports. The root password is random per start, passed to the child in its environment (not its arguments) and kept in `<data_dir>/credentials.json` (0600); a restart on an existing store signs in with the stored password and replaces it. The child gets a minimal environment and its output is never forwarded (stdout is the MCP channel).
- **Crash cleanup.** `Close` stops the child (SIGTERM, then SIGKILL after 10 s). If `ipfs mcp` is killed, a small `sh` watchdog (unix) stops the child within a second, signalling only a pid whose command line still names the store's data path. `<data_dir>/supervisor.json` records the child so the next start stops an orphan the watchdog missed. On Windows there is no watchdog; the next start cannot verify a recorded pid, so the operator stops a leftover `surreal`.
- **Remote mode** (`mode: remote`). `remote.endpoint`, `namespace` and `database` have no defaults. `remote.credential` is an env or file reference whose value is `user:password` (HTTP Basic) or a bearer token; absent means an unauthenticated connection. The namespace and database are created if the credential may; otherwise they must exist.
- **Embedder.** `embedder.base_url`, `model` and `dimensions` have no defaults; `api_key` is an env or file reference. `POST {base_url}/embeddings` with `{model, input}`; a vector of another length is an error. Redirects are not followed. Backend error text is clipped and never includes the request.
- **Egress.** Embedding runs only if the identity that triggered it has an `egress_ack` covering the embedder host (`EgressCovers`, using `AckCovers`), and the remote store host when remote. This is the loop's rule and applies to every identity, configured or not. The operator identity (stdio, `--auth-token-*`) has no `egress_ack`, so it never triggers embedding; that is intended. The check runs before any request is built, and a refusal names the host.
- **Use.** `Server.EnableEmbeddings`, `Server.Embeddings()` (`Index`, `Search`, `Store()`), `Server.CloseEmbeddings`. `ipfs mcp` calls them from `cmd/ipfs/kubo/mcp_embeddings.go`.

## Search index (`mcp-embedding-index-lifecycle`)

Built with and without `noagent`. Off unless the `embeddings` section exists: then the four `ipfs_index_*` tools are not listed (`ipfs_node_status` reports them `not_configured`), nothing is indexed and no embedder is contacted. `ipfs mcp` opens the embeddings service before it enables the agent loop, because both read the tool set once.

- **Policy** (`embeddings.policy`). `auto` (default `false`) indexes text after a successful `ipfs_add`; `mime_allowlist` (default `text/plain`, `text/markdown`; an empty list indexes nothing), `max_bytes` (default 1 MiB) and `chunk_chars` (default 2000) bound what is indexed. The type comes from the file name (`.md`, `.markdown`, `.txt`) or is sniffed from the bytes; content that is not UTF-8 text, contains a NUL byte or is larger than `max_bytes` is left out. Content outside the policy is skipped without a warning.
- **Chunking.** `embeddings.Chunk` cuts at a paragraph break, else a line break, else a space in the second half of the piece, else hard at `chunk_chars` characters. It is a pure function, which is how search finds the text of a hit: the store keeps vectors, not text, so a hit is re-read from the node (`cat` of the row's content path, at most `max_bytes`) and cut again with the same size. Changing `chunk_chars` after indexing needs `ipfs_index_cid` with `force` to repair the index; a hit whose chunk cannot be found is dropped from the result.
- **Trigger.** `ipfs_add` on every transport (stdio, HTTP, AG-UI chat, A2A, the agent loop, UAR in topology B) calls the trigger after the add succeeded, with the bytes it already has. The CID is the one `ipfs_add` returned (the wrapping directory when a `filename` is given; the row's `path` is then `/ipfs/<cid>/<filename>`). A failure, including an unreachable embedder or store, is a warning in the add's `warnings`; the add never fails. Indexing runs inline with a 45 s limit. It adds, pins and announces nothing and reads nothing from the node. Adds made by the WebMCP browser tools are not indexed automatically.
- **Egress.** The calling identity's `egress_ack` must cover the embedder host and, for a remote store, its host, for the trigger, `ipfs_index_cid` and `ipfs_index_search`. The operator identity (stdio, `--auth-token-*`) covers nothing: an add from it succeeds with a warning that names the host and sends nothing, and the explicit tools answer `egress_not_acknowledged`. Use an HTTP principal with `egress_ack` for indexing.
- **Tools.** `ipfs_index_status` (read; contacts the embedder or a remote extractor only when the caller's `egress_ack` covers its host, with one bare GET carrying no credential and no content; an optional `stages` map appears only when the store, embedder or extractor is unavailable); `ipfs_index_search` (read, contentEgress, untrusted content; `cid` restricts to one CID with a per-CID distance query, otherwise the HNSW index); `ipfs_index_cid` (write class; reads one file with `files/stat` and `cat`, skips with `not_a_file` for a directory, `mime_not_allowed` for non-text, `too_large`, `empty` for blank content, or `already_indexed` unless `force`; `ipfs_index_search` reads hits back with `cat` offline); `ipfs_index_reconcile` (write class, destructiveHint; a `dry_run` reports the CIDs it would delete). Embedder and store failures are `index_unavailable` (retryable), a missing acknowledgement is `egress_not_acknowledged` naming the hosts.
- **Pin-aware deletion.** A CID's vectors are deleted only when `pin ls --type=all /ipfs/<cid>` says no direct, recursive or indirect pin covers it, and never when that check or the store fails: the vectors stay and a warning is returned in the output's `warnings` field (`pin_rm`, `pin_update`, `repo_gc` and `ipfs_index_reconcile`). It runs after `pin_rm` (the unpinned CIDs), after `pin_update` with `unpin` (the old CID), and after `repo_gc`, which compares every removed block key, not only the 100-item sample, with the indexed CIDs by multihash (garbage collection reports raw-codec keys, the index holds the dag-pb CID). A recursive `pin_rm` of a directory does not reach files inside it that were indexed separately; `ipfs_index_reconcile` does.
- **Reconciliation** (G12-4). Content unpinned outside `ipfs mcp` (the CLI, another client) is not seen: Kubo has no pin event source and a daemon-wide hook is refused under User Agency. `ipfs_index_reconcile` walks the indexed CIDs in order, one page per call (`limit`, `cursor`), checks each with the same pin check and deletes those no pin covers. The cursor is the last CID of the page, so deleting while paging is safe.
- **Tests.** Unit tests (fake daemon, in-memory store, fake embedder) in `mcp/server/index*_test.go` and `mcp/server/embeddings/policy_test.go`; `test/cli/mcp_embedding_index_test.go` runs a real daemon, the real `ipfs mcp` binary and the real `surreal` binary, with a deterministic fake embedder; `mcp_embedding_index_ollama_test.go` uses a private Ollama with `bge-m3`.

## Content extractor (`mcp-content-extractor`)

Package `mcp/server/embeddings` (`extractor*.go`) and `mcp/server/index_kinds.go`; built with and without `noagent`. Off unless `embeddings.extractor` exists: then no xberg process starts, no extractor request is made, and indexing is exactly the section above (a PDF is `mime_not_allowed`). xberg (`Know-Me-Tools/xberg` v1.3.10, our fork, the same commit as upstream `xberg-io/xberg` v1.3.10 until it diverges) is a separate service called over HTTP with the standard library; nothing of it is linked, there is no cgo and no `go.mod` change. The verified behavior of that release (flags, bind host, offline switch, endpoints that read paths or fetch URLs) is in `openspec/changes/mcp-content-extractor/evidence/2026-10-14-task-1.1/README.md`.

- **Client.** `POST {base}/extract`, multipart: `output_format=markdown`, a `config` field only when OCR is asked for (`{"ocr":{"backend":"tesseract"}}`), and one `files` part named `content.<ext>` with the detected type. It never sends `urls` or `inputs`, the two fields that make xberg fetch a URL or read a server-side path. `extractor.max_bytes` (default 50 MiB) is checked before the request is built; `timeout_seconds` (default 120) bounds the request; redirects are not followed. The response is untrusted: at most 64 MiB, exactly one result, UTF-8 and no NUL in the text, images never read; xberg reports an unreadable file as HTTP 200 with an `errors` entry, and that entry decides.
- **Embedded mode.** `ExtractorSupervisor` runs `xberg serve --host 127.0.0.1 --port <ephemeral> --config <cache_dir>/xberg-serve.json` from `extractor.embedded.xberg_binary` (absolute, never looked up on `PATH`, never downloaded) after an `xberg --version` check against `min_version` (default 1.3.10). It follows the SurrealDB supervisor: own process group, watchdog if `ipfs mcp` is killed, `xberg-supervisor.json` for reaping a leftover on the next start. The environment is minimal: `XBERG_CACHE_DIR` and `HF_HOME` under `cache_dir`, `XBERG_CORS_ORIGINS` set to its own origin (xberg answers every origin by default), `HF_HUB_OFFLINE=1` unless `allow_model_downloads` is true, plus `TESSDATA_PREFIX` and `ORT_DYLIB_PATH` if set. Nothing else of the operator's environment reaches it, in particular not `XBERG_API_ALLOW_LOCAL_URI_INPUTS` or `XBERG_LLM_*`. To pre-warm models for an offline run, use `XBERG_CACHE_DIR=<cache_dir> HF_HOME=<cache_dir>/huggingface xberg cache warm`.
- **Kind routing.** `classifyContent` names the type from a binary signature (PDF, images, ISO media, Matroska, Office/ODF/EPUB zip containers by entry names), then the file name, then the text (JSON, XML, HTML, CSV, TSV, shebang). `ipfs_index_cid` has only a CID, so in practice the signature and the text decide. The kind comes from `mcp/contract/derivations/content-kinds.json`. `text` and bytes of no listed kind stay native; `document`, `code` and `data` go to the extractor, `image` only with `extractor.ocr` and `video` only with `extractor.transcribe` (xberg v1.3.10 lists no audio or video format, so transcription yields `extraction_failed`). A file whose type is not in `policy.mime_allowlist` is `kind_not_enabled`, except UTF-8 text without a binary signature, which stays on the native path as before. The Markdown is cut by the same chunker; rows carry `kind`, `source` (`extracted`, `ocr`; `transcript` for video) and, for derived text, the chunk text itself. `ipfs_index_search` returns that stored text for derived hits without a `cat`, and `kind`, `source`, `mime_type` for every hit (empty for rows written before this change).
- **Skips.** `kind_not_enabled` (stage off or type not allowlisted), `extractor_unavailable` (connection refused, timeout, 502/503/504/429), `extraction_failed` (xberg error entry, malformed or oversize response, HTTP 4xx/5xx otherwise), `too_large` (over `extractor.max_bytes`, no request), `empty`.
- **Egress.** A remote extractor host joins `Config.BackendHosts` (principal preflight) and is checked against the caller's `egress_ack` before the request is built; a refusal is `egress_not_acknowledged` naming the host and the extractor receives nothing. Text files do not need it. An embedded xberg is a local child and needs no entry.
- **No injection.** Extraction issues no `add`, `block/put`, `dag/put`, `pin/add`, `files/write` or `routing/provide`; images xberg returns are never read.
- **Tests.** `mcp/server/embeddings/extractor_test.go` (client against an `httptest` fake), `extractor_supervisor_test.go` (the test binary stands in for xberg), `mcp/server/index_extractor_test.go` and `index_kinds_test.go`; `test/cli/mcp_extractor_test.go` (`TestMCPExtractorDisabled`) and `mcp_extractor_xberg_test.go` (`TestMCPExtractorXberg`: real xberg v1.3.10, real surreal, Ollama `bge-m3`; skips unless `IPFS_MCP_TEST_XBERG` is the absolute path of the binary).

## Media describer, bulk indexing and search routes (`mcp-media-describer`, `mcp-whole-node-indexing`)

Built with and without `noagent`; off with the rest of the embeddings feature when there is no `embeddings` section. Details for operators are in [`docs/mcp/embeddings.md`](../../docs/mcp/embeddings.md); this section is the code map.

- **Describer** (`embeddings/describer.go`, `embeddings.describer`). A standard-library client of `POST {base_url}/chat/completions`. The request body is streamed through a pipe with an exact `Content-Length`, with the media as a base64 `data:` URL in an `image_url` part (or a `video_url` part with `fps` and `media_resolution: "default"` when `kinds` lists `video`); the node never sends a URL. Size caps, the egress check (`*EgressError`) and the hourly limit (a sliding window shared by every caller, spent only after the egress and size checks) run before any request exists. Errors are `ErrDescriberDisabled`, `ErrDescribeTooLarge`, `ErrDescribeRateLimited`, `ErrDescriberUnavailable`, `ErrDescribeFailed`. The fixed instruction is `DescriberInstruction` (not a config key). Chunks carry `source: description` and `described_by` (the configured model name).
- **Stages** (`index_file.go`). `indexFile` routes by kind and is the one per-file path of `ipfs_index_cid` and the bulk run. For an image or video, `indexMedia` runs the extractor stage (OCR or transcription, when on) and the describer stage independently and stores what both produced in one `Service.Index` replacement (`Document.Segments`), so chunk indexes continue across stages and `force` replaces all of them. A refused or failed stage is a warning (`_meta[contract.StageWarningsMetaKey]`, entries `stage:reason` with a fixed reason code, never endpoint text) while another stage has text; an exhausted hourly limit is always `resource_exhausted` so a retry can complete the file.
- **Bulk run** (`index_bulk.go`). One goroutine per run (`bulkRunner`), at most one live (`Server.bulk`). The walk lists pins (`pin/ls`, recursive and direct, sorted) and MFS, stats each entry with `files/stat` and descends with `ls`, all with `offline: true` and a per-command deadline, then hands the file to `indexResolved`. `walkTree` is the one walk of both sources. MFS is read through its root CID (`files/stat /` once, then `/ipfs/<root>/<path under mfs_root>`): the daemon's `files/ls` and `files/stat` on an MFS path ignore `offline` and would fetch a lazily copied directory over bitswap. The cursor is a pin plus the path inside it, or an MFS path. State (`embeddings.Run`: cursor, counts, caps, starter) is saved in the SurrealDB table `ipfs_bulk_run` through `embeddings.RunStore` after each tried file. A run stopped by `ipfs mcp` exiting is `paused`; one found `running` with no live runner (a crash) is stored `paused` at startup and by a start, and a status read only reports it as `paused` (a read never writes; cancel checks and writes under the bulk lock); nothing resumes without a confirmed `ipfs_index_bulk_start` with `resume`. `Server.StopBulk` runs from `CloseEmbeddings`. The test seams are `Server.bulkClock` and `Server.bulkSleep`.
- **Gate integration.** `bulkPreflight` (registered in `attachEmbeddings`, run by the tool handler before the confirmation) refuses a start the calling principal cannot make, so nobody is asked to approve it. `gate.summaryArgs` (`summaryArgs`) gives the confirmation text the effective sources, caps and every non-loopback host; the argument hash the confirmation binds to is unchanged.
- **Routes** (`index_routes.go`). `EnableIndexRoutes(origins)` (called from `cmd/ipfs/kubo/mcp_embeddings.go` unless `embeddings.search_route.enabled` is false) lets `mountIndexRoutes` mount both routes in `NewHTTPServer`. They run `indexSearch`, `indexStatus` and the bulk status of the same server after the tool's own group and egress checks, with strict CORS from `agent.origin_allowlist`. `POST /index/search` passes `searchLimiter` (`index_limit.go`: a per-identity token bucket and in-flight caps, `429` with `Retry-After`). `ipfs_index_search` takes `kinds` and `sources` filters; `Service.SearchFiltered` over-fetches nearest rows and keeps those that pass until `top_k` do.
- **Tests.** `embeddings/describer_test.go`; `index_describer_test.go`, `index_bulk_test.go`, `index_bulk_gate_test.go` (and `_agent_test.go`), `index_routes_test.go`, `embeddings_describer_config_test.go`; helpers in `media_helpers_test.go` and `bulk_helpers_test.go` (a fake node with pins, directories and MFS that answers only offline reads). `test/cli/mcp_bulk_test.go`, `mcp_bulk_ollama_test.go` (real Ollama `bge-m3` and surreal) and `mcp_describer_test.go` (`TestMCPDescriberRealService` skips unless `IPFS_MCP_TEST_DESCRIBER_URL` and `IPFS_MCP_TEST_DESCRIBER_MODEL` are set).

Settled UAR approvals share the same resolved-history ring while retaining their distinct backend authority. Synthetic IDs are random per owned pending interruption and stable across its refresh/retry; the original backend interruption ID remains unchanged in resume requests. An acknowledged approved resume records consumed approval without an execution outcome or node receipt. Unacknowledged resumes remain open under the existing reopen rules. Retained summaries omit backend prose, arguments and continuation handles; repeated settlement cannot renew retention.

The HTTP listener serves protected `GET /decisions` and `GET /decisions/{id}` independently of the LLM backend and `/agui`. The existing UI bearer works directly; console JWTs need the operator's explicit `auth.oidc.routes` entry `decisions`, whose default remains session-only. Authentication uses the same Host, strict origin, fetch metadata, body limits and verifier chain as other mounted routes. Actual authenticated ui/human-mcp/a2a/uar identities can read their own records without a write or egress grant; anonymous loopback and admin identities cannot. Unknown, foreign and evicted IDs return the same unavailable response. The projection has bounded summaries and real outcome facts, with no tokens, raw arguments, backend prose or private owner binding. Actions require an exact owned continuation and independently authorized answering route.

List pages default to 50 and allow at most 100 items, capped at 1 MiB with 256 KiB per item. Signed 60-second cursors bind an opaque keyed owner tag, epoch, own revision, sort key and limit. Tampered or foreign cursors return generic 400; authenticated own stale cursors return 409. Restart loses the process signing key, so an old cursor also returns generic 400. Clients discard a rejected cursor and read a fresh first page once, then show any persistent failure. No cursor or read grants approval authority. Live UAR observations derive from idle owned threads, one current approval per thread and at most 64 globally; running source fields are not read concurrently. Backend consumption never supplies a node receipt.

Set `agent.decisions.enabled` to false to leave these paths unmounted and release closed observer history. Stdio, HTTP-off and `noagent` builds keep no closed observer history. The winning invocation still receives its truthful tool-result metadata, and underlying confirmation/native prompts and single-use enforcement remain effective. No repository, durable history, extra listener or external service is involved. The protected idle subscription is `GET /decisions/events` on that same listener.

Each accepted builtin or UAR user message receives a fresh server-assigned `activity_id`. Its owned resumes, queued calls, interruptions and decision observations keep that ID even when the client changes `runId`; another message on the same conversation receives a new ID. The label does not derive from a principal, subject, backend interrupt, prompt or operation digest. Unknown non-chat activity stays omitted. The interrupt's optional `metadata["ipfs-mcp"].activity_id` carries the association independently of run-facts emission; the later facts adapter receives the same ID through internal run events. Standard `RUN_STARTED`, tool-result metadata and minimal decision notifications gain no extra fields. A client activity hint cannot select ownership, resume an interrupt or approve a write, and the correlation promises no durable history or cross-restart recovery.

Decision mutations publish internal invalidations containing only `{id, state, revision}`. Revisions use the same owner-filtered version calculation as snapshots; actual execution state takes precedence over consumed approval in the hint. Creation, authorized resolution, claim, real progress/outcome, expiry and retained-record removal invalidate only that full private owner. Removal preserves the last known state as a cache invalidation, without asserting a new outcome. UAR visibility changes use a separate bounded minimal marker index, at most 64 and one current idle approval per owned thread. Markers hold no summary, arguments, receipt or continuation; a digest tracks changed visible source facts, and old backend generations cannot republish after replacement.

Subscriptions are bounded to four per full identity, 16 per configured principal and 64 total, with 16 queued hints each. Initial snapshot-required metadata is captured atomically after registration and kept separate from the queue. Publishers never wait on client I/O or acquire a source/session lock. Overflow replaces that subscriber's pending queue with one latest-own-revision snapshot-required marker. Disable/unsubscribe drains and closes queues; observer disable leaves underlying approvals effective. Source reads take the UAR lock before the broker lock, and broker publication never reverses that order. Deadline/wake and sweep hooks cover node expiry, seven-day history cleanup and UAR projection expiry. The publication layer does not promise replay or grant approval.

The idle SSE feed authenticates every connection through the same verifier and explicit OIDC `decisions` route grant as the list. Its first named event is `ipfs.decisions.snapshot_required`, captured after atomic subscription; subsequent events are minimal `ipfs.decision.changed` hints or an overflow snapshot marker. Each complete event is at most 1024 bytes. There is no SSE `id`, durable replay or URL credential; `Last-Event-ID` is ignored and reconnect starts with a fresh snapshot marker. Read-only nonbrowser GET requests retain the established no-Origin behavior; supplied Origin and fetch metadata still pass shared protection.

A stream sends a keepalive comment every 25 seconds and gives each write at most five seconds. Writers without deadline support fail closed before a subscriber is allocated. Lifetime ends at the earliest verifier verdict expiry, actual JWT/session expiry, or 15 minutes, without middleware clock-skew grace. Every frame and comment checks validity; a bounded cancellation watcher interrupts blocked writes on expiry, disconnect, known owner/principal invalidation, feature disable or listener shutdown. Successful short writes clear their deadline before the idle interval. Subscriber exhaustion returns 429 with `Retry-After: 5`; cancellation releases the slot and drains queued hints. Existing verifier/configuration objects are immutable until restart; the internal known-invalidation hook closes matching read resources without adding polling or an authentication service.

One scheduler starts only when the enabled HTTP listener actually serves. It uses broker deadline/wake hooks, never client callbacks or source/session locks, and sweeps unattended approval expiry, UAR visibility expiry and seven-day history removal. Listener cancellation closes streams and joins the scheduler. Feature-off, HTTP-off, stdio and `noagent` builds start no observer scheduler; `nomcp` omits the command wiring. Pending approvals and tool invocation retain their existing authority and confirmation requirements. Authored stream fixtures cover minimal wire shapes, real-listener deadline support, exact authentication lifetime, overflow reconciliation, subject isolation, quotas, slow writers, unsupported writers, disable and concurrent shutdown. Their execution belongs to the final integration gate.

Decision action hints use the current owned interruption, not read access alone. The read handler checks the same credential through the existing protected POST `/agui` policy with a body-free no-op sink; it never calls the run handler. The route must actually be mounted, its verifier must still admit the same full identity, and its POST Origin policy must pass. A decisions-only JWT, expired credential, changed route mapping, or read-only a2a/uar identity receives no continuation. Probe responses, headers and credentials are discarded. A locator contains only method, route, owned thread and current interrupt ID; it is neither consent nor a token.

For node confirmations, hints also require an idle unexpired owned session, retained backend snapshot, exact first queued call, immutable arguments, confirmation session/owner, reviewed digest/destination, daemon endpoint and applicable chat resolver. Missing optional legacy display metadata keeps the old argument binding mandatory. Approval additionally needs the caller's effective tool grant and existing content-egress permission. Native-required approval always stays false; the existing locator supports genuine denial or native wait. Already approved native items may retain wait, but never advertise denial of an approval already recorded. Claimed, terminal, stale or revoked items expose no continuation. Reads take source locks before the broker and invoke no resolver or tool. The existing resume endpoint rechecks ownership, digest, native policy and the single-use claim, so a cached locator cannot override denial or replay a write.

UAR locators come only from the current owned idle thread's shown unanswered backend interruption. They use the existing AG-UI resume translation, which preserves the original backend interrupt ID and never calls the node broker for a synthetic decision. Unknown reviewed digests stay absent. An acknowledged backend approval can be consumed with no reported execution; backend text and stream completion create no node receipt. Item reads expose only retained actual execution evidence, and successful receipts must match the node decision, tool, reviewed digest, completion and node-handler provenance. Failed, unknown and not-started outcomes remain distinct and have no success receipt. Unknown/evicted history still means unavailable evidence, not operation failure.

Accepted AG-UI runs emit one standard `CUSTOM` event named `ipfs.run.facts` after `RUN_STARTED` and the optional immediately following catalog advertisement, before tool or text events. The value identifies the exact thread, run and server-owned activity. Builtin facts come from the already selected `run.snap` and actual policy-filtered `run.offered`: exact offered names, loaded contract denominator with `kubo_contract` scope, SHA-256 of the retained full system prompt, selected model/host, process-conversation memory, and bounded effective acknowledged host labels. Every supplied fact names its provenance. The event contains no prompt text, key fingerprint, argument or credential. An empty known offer/acknowledgement remains explicit; unavailable facts stay absent. Backend host projections contain only host/port; configured URLs do not establish inference placement, so placement is omitted.

Resumes retain their original prompt/backend snapshot even after a model/prompt settings change, and new messages use the new snapshot. Observation-only native waits and local UAR interruption transitions may omit facts rather than reconstruct a model invocation. UAR constructs only locally established selected backend endpoint and effective acknowledged labels: final tools, catalog total, model, prompt and memory stay absent without a validated backend report. Incoming UAR CUSTOM events remain blocked, including spoofed `ipfs.run.facts`. ### Typed turn references

`forwardedProps.ipfs.context` accepts at most 16 uniquely identified references and 16,384 raw UTF-8 JSON array bytes, including whitespace and escapes. The builtin and UAR adapters frame accepted references as bounded untrusted user data with the existing delimiter escaping, preserve ordinary egress/confirmation checks and never read, resolve, fetch, pin or announce a reference implicitly.
