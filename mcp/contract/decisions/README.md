# Current-identity decisions read surface

Canonical route descriptor: `routes.json`, validated structurally by `routes.schema.json`. Wire shapes: `decision-read.schema.json`, reusing `confirmation/confirmation.schema.json#/$defs/DecisionObservation`. ADR-0017 and operator UI-05/06/07/11/12/13 govern. This is I/1.1's contract; no server/UI code or generated artifacts are implemented here.

## Mount and authorization

Mount `/decisions` and its subtree through the existing MCP listener's `HTTPServer.Mount`, with explicit accepted kinds ui, human-mcp, a2a and uar. Refuse admin and anonymous identities, including an otherwise anonymous-loopback listener. Require actual authenticated Identity/TokenInfo; never obtain read ownership from a default `LocalPrincipal` fallback. Reuse Host/Origin/fetch-metadata/body protections and strict `agent.origin_allowlist` CORS for GET/OPTIONS, Authorization/content-type, exposed Retry-After, no wildcard/no credentials header. Cookies are never parsed; the session gateway may forward the ordinary validated ID token in Authorization. No credential goes in a URL or event.

JWTs need the new explicit `auth.oidc.routes` key `decisions`; the default remains `["session"]`. Route-aware resolution must choose an allowed tool principal for that subject, never grant an admin identity broader observation. Reads require no extra tool-group, write-group or egress grant because they observe only records already owned by the identity. Observation does not create any resolver rights. Static credentials remain supported. Authentication failures and unsupported kinds use existing 401/403 behavior.

Provisioning requirements are additive to the existing credential mode, not a new flow. Desktop reuses its already provisioned sidecar UI bearer and existing endpoint; no decisions token, extra pairing, OAuth scope or write grant is issued. Console mode reuses the already issued console ID token, configured issuer/audience/subject mapping and Authorization forwarding; configure the MCP server's existing OIDC route list to include decisions and route protected GET /decisions* to that listener through the existing trusted console path. `config/examples/decisions-oidc.json` demonstrates this explicit server grant. No deployed gateway/config is changed by this contract task. UI distinguishes unmounted404 from credential/route-grant401/403 and states the configuration limitation; it must not trigger re-pairing, invent a local fallback endpoint, broaden scopes or grant itself /agui resolution. A read-only a2a/uar identity remains read-only even when it can see its own record.

`agent.decisions.enabled` defaults true behind the already opt-in MCP HTTP listener. False unmounts all three paths, closes subscribers and releases observer history. `noagent`/`nomcp` and HTTP-off have no read surface. This works without an LLM backend, /agui mount or an active run; it does not start another listener or call any external service. Turning it off leaves original confirmation/native prompts effective. D/4.2 owns the generated config reference, defaults/changelog documentation and disabled-state test mapping at its later assignment.

Filter *before* pagination and event publication using the full `Principal.BindingKey()`, including OIDC subject, across that identity's sessions. Do not filter by configured principal ID alone. Two subjects sharing a principal cannot read each other's details, continuation or events. Pending paired-local-app native requests belonging to another identity are absent; the Desktop paired queue is a separate domain. Never log or project raw binding keys, JWT subject, confirmation/request-state handles, grants, credentials, sensitive arguments or backend response bodies. Safe configured display authority fields remain as specified by D/1.1.

## List, item and errors

`GET /decisions?limit=50&cursor=...` accepts only limit (integer 1–100, default 50) and a server-issued cursor. Unknown/repeated parameters, body, caller-selected identity filters and any URL credential parameter are invalid_argument 400. Never echo raw query text. Each atomic response has server_epoch, opaque own revision, history_started_at, retention disclosure, items and page. Sort newest created_at first, breaking ties by opaque ID descending. No global retained-count or other-identity activity metric appears.

`GET /decisions/{id}` returns the same snapshot metadata and one current DecisionObservation. Decode exactly one safe opaque ID; no path traversal or alternate arbitrary lookup. Reserve literal `/decisions/events` before item routing. Unknown, foreign and evicted IDs use indistinguishable 404 behavior. A missing old completed receipt is unavailable history, not proof of operation failure; a restored pending/approved card unknown after restart may need resubmission with a new user request. No read runs a model, RPC write or resolver.

GET and CORS OPTIONS are the only methods. Refuse HEAD, POST, PATCH, DELETE and other methods with 405 and `Allow: GET, OPTIONS`; accepted preflight returns no identity data. Cache-Control is no-store on snapshots/details/errors and the stream. Request/auth/Origin/mount errors can retain the shared HTTP layer's plain/empty bodies; route-generated errors follow ReadError. Cursor refresh-required uses 409 and safe current own epoch/revision; subscriber exhaustion uses 429 and Retry-After 5.

Snapshot item encoding is capped at 256 KiB and each list response at 1 MiB. Apply safe D/1.1 projection bounds before encoding. Stop a page before exceeding the byte cap and return has_more/next_cursor if needed; never silently omit additional items while saying has_more false. A record that cannot be represented safely within the item cap is an explicit safe internal read failure, not a successful truncated receipt or an unbounded allocation. Do not invent identifiers or expose omitted sensitive details to make the page fit.

## Retention and pagination consistency

Retain at most **200 resolved records total per server**, expiring at seven days, whichever eviction applies first. Filter that process-wide ring for each caller. This is up to 200 retained results, not 200 promised per identity. Other identities can cause eviction but never make their content visible. Set `retention.scope: server`, max_resolved 200, max_age_seconds 604800 and resets_on_restart true. `history_started_at` identifies this process's observer start; history and random epoch reset on agent-server restart and never enter the Kubo repository or durable storage.

Pending, approved and running authoritative records use existing broker/thread quotas and are not evicted merely to make resolved-ring space. Derive live observations from those authorities rather than duplicating unbounded live state. Bound new UAR live projections to 64 globally and one current open approval per existing owned thread; source eviction removes the projection, not the underlying node confirmation or a replay restriction. The observer never denies/approves/retries a write to enforce its memory budget. Resolved denial/expiry and real terminal success/failure/unknown are retained independently of token-grace cleanup. Bare consumed executed without outcome evidence never becomes success; lost outcome/history must remain unreported/uncertain.

Use stateless authenticated cursors bound to private identity tag, random process epoch, own snapshot revision, last sort key, chosen limit and expiry (60 seconds). HMAC-authenticate with a process secret. Do not serialize raw BindingKey/subject in base64 token bodies: use a process-keyed opaque identity tag or equivalent confidentiality. The existing unsigned generic pagination cursor is insufficient and must not be reused unchanged. Foreign-owner/tampered/malformed cursors get the same generic400. A previously valid caller cursor whose epoch/revision/expiry changed gets 409 cursor_refresh_required, never silently skips or duplicates items. A changed limit with a cursor is invalid. No cursor is an approval/continuation token. Authenticate the signature and owner before reporting staleness. A real process restart discards the HMAC key, so its old cursor cannot be authenticated and receives the same generic 400 as tampered input; do not infer legitimacy from an unsigned epoch. When a client-generated paginated request receives cursor 400 or authenticated-stale 409, discard that cursor and reconcile from a fresh first page once. A failed fresh first page is surfaced, not retried in an unbounded loop.

Use opaque per-identity revisions as equality tokens; do not expose a global incrementing operation count. Update them on the caller's relevant creation, resolution, claim, execution result, expiry and history removal. An eviction affects only the identity losing that visible record. Record expiry changes with a bounded scheduled wakeup; relying only on the next active tool request leaves idle screens stale.

## Idle SSE and snapshot reconciliation

`GET /decisions/events` uses authenticated fetch streaming with the same credential mode as list/item. Do not place a bearer in query parameters or assume native EventSource can set Authorization. It stays separate from run-bound AG-UI and works while no chat run is active.

SSE framing uses these event names and JSON data shapes:

```text
event: ipfs.decisions.snapshot_required
data: {"server_epoch":"epoch_fixture_0001","revision":"rev_fixture_1","reason":"initial"}

event: ipfs.decision.changed
data: {"id":"cf_3pQm8vK2xR7tLw9a","state":"running","revision":"rev_fixture_2"}
```

SnapshotRequired's reason is initial, overflow or reconcile. DecisionChanged contains **only id, state and revision**. State is an invalidation hint: actual execution state when reported, otherwise legacy approval state. It is not a derived presentation, success receipt or capability. Re-fetch the protected item/snapshot before drawing terminal truth. Never include tool, targets, arguments, credential, principal or receipt in the feed. Emit a change for creation/approval/denial/expiry/claim/actual completion and retained record removal; when a record disappears the hint only invalidates its cached item, not a fabricated final outcome.

I/1.5 may mirror the same owned minimal hint as an AG-UI CUSTOM event named ipfs.decision.changed, referenced by the AG-UI schema. This does not replace the dedicated idle subscription, carries no cross-owner/native-domain information, and is independent of the A2UI capability/switch. No UAR CUSTOM passthrough is authorized by this additive event name.

Subscribe atomically before reading current own revision, then send an initial snapshot_required on every connection. The client buffers invalidations while loading authenticated snapshot pages and rejects 409-stale pages. At fetch start clear earlier invalidation hints that the upcoming snapshot supersedes; if new hints/overflow occur during loading, reconcile/refetch before claiming current state. Revision equality is the only comparison; do not sort/parse opaque revisions. A delayed hint may cause one extra read, which is preferable to missing a change. Identity switch aborts stream/fetch and discards the old identity cache.

The stream supplies no durable replay. Omit SSE `id`; ignore Last-Event-ID for replay and always send the fresh initial snapshot-required marker. On reconnect/epoch change, discard stale pagination and reconcile a new snapshot. Old handles do not become resumable. Client frame-coalesced invalidation can limit rendering/read bursts; it never discards an overflow marker or silently declares history complete.

Bounds: at most 4 streams per full identity, 16 per configured principal and 64 total, with 16 queued hints per subscriber, maximum 1024 encoded bytes per event, 25-second comment keepalives, 5-second write deadline and maximum 15-minute connection lifetime. Principal quotas combine subjects without sharing their data. Refuse excess allocation with 429/Retry-After 5. On queue overflow atomically replace pending hints with one latest-own-revision snapshot_required; do not block mutation publishers on client I/O. If the client cannot receive within the write deadline, disconnect and release subscriber resources. Do not invoke callbacks or acquire session locks while holding broker locks.

Close no later than the AuthVerifier verdict expiration (the existing static verifier's verdict is short-lived), bounded lifetime, known credential/principal invalidation, feature disable, context cancellation or disconnect. Do not extend a stream through a JWT's expiry using HTTP clock-skew grace. Every reconnect re-authenticates; no unconfigured background identity lookup, credential refresh service or polling endpoint is added. Send no identity data after the validity deadline; keepalive is not a validity extension. Cancellation/overflow do not cancel/retry an underlying write.

## Authorized continuation and UAR

### I/1.4 activity correlation amendment (2026-10-20)

`ActivityId` in the confirmation schema is a bounded opaque server-assigned identifier. Assign a fresh ID for each accepted new user activity, including a new message on an existing conversation; retain it for that activity's authorized resumes, queued calls and interruptions even when each resume has a new runId. Rejected input creates no accepted activity. It is neither client runId/threadId nor an ownership or authorization key. Do not derive it from a principal/subject/BindingKey, token, prompt or arguments. No client-supplied ID is accepted as activity authority.

The optional exact wire locations are `CUSTOM ipfs.run.facts.value.activity_id`, `Interrupt.metadata["ipfs-mcp"].activity_id`, and `DecisionObservation.activity_id`. They all reference the same ActivityId definition and must agree for the same accepted activity. Preserve ordinary RUN_STARTED fields, AG-UI SDK compatibility and existing event ordering; do not add an unknown RUN_STARTED key or a new handshake. Run facts remain optional and are implemented by C. Interrupt activity metadata is independent of `agent.run_facts`: when facts are off, a trusted interruption still carries the activity ID needed to associate its decision. No synthetic facts event is emitted merely to bypass that off switch.

Clients use the server-projected ID only as a display grouping/join hint within authorized data. Bind facts to the current thread/run and associate an interruption via its actual confirmation ID and trusted activity metadata. Inbox rows may then use the same observation ID; missing activity_id means association is unreported, not permission to infer it from tool text, targets or a backend ID. An activity may have multiple decisions; a decision still has its own immutable ID/digest and authority. UAR reports use server-owned activity correlation, never raw backend CUSTOM/activity claims.

The idle SSE payload stays exactly id/state/revision. Fetch the authorized observation for activity_id; do not expand minimal notifications or expose other owners' associations. Activity IDs grant no resume, lookup or approval rights and add no generic activity endpoint. Restart, eviction, identity changes and the existing bounded retention still apply; the ID does not promise a durable transcript or cross-restart recovery. Non-chat/native/MCP records without a known accepted activity omit it honestly. Disabling inbox reads does not change existing interruption semantics.

Reuse D/1.1's exact DecisionObservation/actions/DecisionContinuation. Only an owned open chat interruption may carry continuation locators for existing authenticated POST /agui resume. Recheck owner, exact thread/interrupt, immutable operation/reviewed digest, expiry, allowed resolver and single-use claim. Native-required approve stays false; deny or existing wait semantics do not synthesize native presence. Host/native/paired requests without owned continuation name the known authorized answering surface instead. No `/decisions/{id}/resolve` or generic approve endpoint exists, and event observation grants no rights.

UAR records remain `source: uar`, `source_kind: backend_approval`, synthetic cf_uar_ IDs and uar: labels. Project only the authenticated chat owner's UAR thread; do not expose the separate configured uar MCP principal's node records to it. Resume translates through the existing owned UAR interruption, never Broker.Resolve on the synthetic ID. Stream completion/text output is not a node success receipt. Retain only supported actual facts; backend outcome/context gaps stay unreported.
