## What the verification changed

1. **`catalogId` is an identifier, not an endpoint (A2).** The published ID is a stable URI string under the fork's repository path. It is never fetched, so it adds no endpoint that Kubo's "every hardcoded endpoint must be configurable" rule would cover. The contract's short `catalogId` (`ipfs-mcp`, `derivations/a2ui-components.json`) is kept as `A2UI_CATALOG_SHORT_NAME`; the A2UI document needs a URI, so the two are mapped, not merged.
2. **Zod 3 and Zod 4 coexist (A14).** `@a2ui/web_core` 0.12.0 builds on Zod 3, and `@a2ui/react` lists `zod ^3.25.76` as both a dependency and a peer, which conflicts with the pinned Zod 4.6.5 (pnpm reports it as an unmet optional-style peer; `@a2ui/react` does not import `zod` at runtime). The A2UI property schemas use `zod-v3`, an alias of the exact `zod@3.25.76` that `@a2ui/web_core` resolves, so the types and the runtime introspection agree. The contract-derived component data schemas are Zod 4. The adapter validates with the Zod 4 schemas, so the contract remains the single source of truth.
3. **The MCP Apps default CSP has no `font-src` (M4).** A bundled `@font-face` with a `data:` or relative URL can be refused. Fonts are registered from embedded bytes with `FontFace`; if that API is missing the font stacks fall back to system fonts without layout change. `mcp/app` should not add `resourceDomains` for fonts.
4. **Host colors are partial and use `light-dark()` (M6, M7).** Adopting some host colors beside brand accent and state colors would break the contrast the brand verified. The default policy takes only `theme` from the host.
5. **Peer packages for `mcp/app` (M10).** `@modelcontextprotocol/core` and `/client` are peers of `ext-apps` but are not in `versions.toml`.

## Not verified here

- Rendering inside a real MCP Apps host (Claude Desktop, Codex desktop, Kimi desktop). The `webmcp-host-spike` and `mcp-app-views` changes own that.
- That a third-party A2UI renderer other than `@a2ui/react` accepts the manifest. The manifest is validated against the official v0.9 envelope schema shipped in `@a2ui/web_core` (see `tests/a2ui`).
