## 1. Tasks

- [ ] 1.1 Bulk run engine: enumerate recursive and direct pins (`pin/ls`) and MFS under `bulk.mfs_root` (`files/ls`) per `bulk.sources`, descend directories with `ls`, and index each UnixFS file through the `ipfs_index_cid` path, skipping `already_indexed`; every `cat` and `ls` carries `offline: true` and a file with missing blocks is skipped `not_local`; enforce `max_files_per_run`, `max_bytes_per_run` and `files_per_minute`; allow one run at a time; persist run state (cursor, counts, starting principal, caps, status) in the store; on `ipfs mcp` start a `running` run becomes `paused` and is never resumed without a request. Acceptance: tests for each cap, a second start refused while one runs, a restart leaving the run `paused`, and a resume continuing from the cursor without re-indexing done files.
- [ ] 1.2 Tools per the contract: `ipfs_index_bulk_start` (write class; confirmation text names the sources, the caps and every egress host; `resume: true` asks again), `ipfs_index_bulk_status` (read: status, counts by kind and by skip reason, current cursor, last errors) and `ipfs_index_bulk_cancel` (write class). Acceptance: schema-conformance tests against the contract; the existing confirmation tests pattern shows both write tools refused without a confirmation on stdio, HTTP, AG-UI and A2A.
- [ ] 1.3 Principal and egress: the run executes as the starting principal; start is refused unless that principal's `egress_ack` covers every host the configured stages may contact (embedder, remote store, remote extractor, describer), and the check repeats before each file; the operator identity (stdio, `--auth-token-*`) is refused with `egress_not_acknowledged` as in G12. Acceptance: tests for a refused start naming the missing hosts, an accepted start, and the operator identity refused.
- [ ] 1.4 No CID injection, no network fetch: a test with the recording fake RPC asserts that a run issues no `add`, `block/put`, `dag/put`, `pin/add`, `pin/update`, `files/write`, `files/cp` or `routing/provide`, and that every `cat` and `ls` is offline; a `test/cli` test (`TestMCPBulkIndexNoInjection`) builds a node with pins and MFS files, runs a bulk index with a local fake embedder, and asserts that `ipfs pin ls`, `ipfs refs local` and `ipfs files ls -l /` are identical before and after. Acceptance: both tests exist; the `test/cli` test uses its own `IPFS_PATH` and non-default ports.
- [ ] 1.5 HTTP routes per the contract's route descriptor: `POST /index/search` (body and response are the `ipfs_index_search` schemas) and `GET /index/status` (`ipfs_index_status` plus the bulk summary), mounted only with `--http`, an `embeddings` section and `search_route.enabled` not `false`; principal kinds `ui` and `human-mcp` with the `index` group; `admin` refused; the same `egress_ack` check as the tool; the listener's `origin_allowlist` CORS rule and body limits; errors mapped per the descriptor. Acceptance: tests for 404 when unmounted, 401 without a token, 403 for `admin` and for a principal without `index`, an egress refusal naming the hosts, and a response that validates against the output schema.
- [ ] 1.6 `--print-rpc-allowed-paths` includes `pin/ls`, `files/ls`, `files/stat`, `ls` and `cat` when the bulk tools are selected. Acceptance: a test of the printed list with and without the bulk tools.
- [ ] 1.7 Disabled states: with `bulk.enabled: false` the three bulk tools are not listed; with `search_route.enabled: false` both routes answer 404 and nothing is read or dialed; with no `embeddings` section none of them exists. Acceptance: unit tests plus `TestMCPBulkIndexDisabled` and `TestMCPIndexSearchRouteDisabled` in `test/cli/`.
