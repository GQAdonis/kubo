- [x] 1.6 Implement `confirmation.resolvers`, `confirmation.cli` and `confirmation.ttl` (operator decision 2026-10-11; owner `mcp-server-engineer`; replaces the R11-Q02 rejection at validation). Semantics, as described in `mcp/contract/config/ipfs-mcp-config.schema.json` and ADR-0003 (amendment of 2026-10-11): (a) `resolvers` holds unique items from `desktop`, `macos-localauth`, `linux-polkit`; absent means all three; it narrows the resolvers the effective modes enable and is applied after mode resolution whatever the source (`--confirm`, `IPFS_MCP_CONFIRM`, `confirmation.modes`, default), so it can only make the gate stricter; `[]` runs none of the three; `cli` is not narrowed by it; a startup warning is printed when the narrowing removes every resolver the modes asked for. (b) `cli` is a boolean, default `false`; `true` enables the `cli` mode as if `cli` were in `confirmation.modes` (the `principals[].shell_capable` rule and the TTY requirement apply; with `confirmation.modes` absent it adds `cli` to the default modes `native`, `desktop`; per R12 SEC-M1 the `cli` resolver never approves a confirmation from the stdio local principal, so a non-eliciting stdio client with only `cli` gets `confirmation_unavailable`, with a startup warning); `--confirm` and `IPFS_MCP_CONFIRM` still win; an explicit `cli: false` while `confirmation.modes` lists `cli` is a validation error. (c) `ttl` is a Duration, default `120s`, must be at least `1s` and at most `10m` (otherwise a validation error), and governs pending confirmations, confirmation tokens, and the confirm channel and `ipfs mcp confirm` expiry; expiry is denial. Remove `TestUnreadConfirmationKeysAreRejected` and replace the "Not supported" notes in `docs/mcp/config-reference.tests.json`. Verify: unit tests in `mcp/server` cover each rule above, including the disabled state (keys absent behave exactly as before: all host-offered resolvers of the effective modes, no `cli`, 120 s); `go test ./mcp/... ./cmd/ipfs/kubo/` passes; `make build && go test ./test/cli/... -run TestMCPConfirm -v` passes; `python3 docs/mcp/config_reference.py --write` then `--check --ipfs cmd/ipfs/ipfs` reports OK with every test named in the sidecar present
