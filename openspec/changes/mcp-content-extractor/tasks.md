## 1. Tasks

- [ ] 1.1 Verify, against the `xberg-cli` `v1.3.10` release asset for the build host (checksum recorded), and write down with commands and output: the `xberg serve` flags for host, port and cache directory; whether it binds only the requested host; which flag or environment variable stops runtime model downloads, and what `/extract` returns when a needed model is missing; whether any endpoint reads a server-side file path or fetches a URL. Then add a standard-library client for `POST /extract` (multipart `files`, `output_format: markdown`) in `mcp/server/embeddings/` with a bounded timeout, the `extractor.max_bytes` cap applied before the request is built, and the response validated as untrusted input. Acceptance: the findings are saved in the evidence folder the lead names; unit tests against an `httptest` fake cover success, a refused oversize body (zero requests made), a malformed response (`extraction_failed`) and a timeout; `git diff` shows no change to any `go.mod` or `go.sum`.
- [ ] 1.2 Embedded mode: start the operator-supplied `extractor.embedded.xberg_binary` (absolute path, no `PATH` lookup) as `xberg serve` on `127.0.0.1` with an ephemeral port and `cache_dir`, check `min_version`, disable model downloads unless `allow_model_downloads` is true (using the mechanism found in 1.1), stop it when `ipfs mcp` exits and clean up orphans, reusing the `surreal` supervisor pattern. If 1.1 found no working offline switch, the start logs a warning that names the Hugging Face Hub and the docs task (`vector-search-contract` 1.7) is told. Acceptance: tests show a relative path is refused, the bind host is loopback, an older version is refused, and the process is gone after `ipfs mcp` exits.
- [ ] 1.3 Kind routing: detect the MIME type (file name, then sniffing), map it to a kind with the contract's `derivations/content-kinds.json`, keep `text` on the native G12 path, send `document`, `code` and `data` (and `image` with `ocr`, `video` with `transcribe`) to the extractor, chunk the returned Markdown with the existing chunker, and store derived chunks with `source` (`extracted`, `ocr` or `transcript`), `kind`, `mime_type` and the chunk text (additive store fields). Search returns stored text for derived entries and keeps re-reading for `text` entries. Acceptance: one test per kind; the existing G12 index tests pass unmodified; a search over a derived entry returns its stored text without a `cat`.
- [ ] 1.4 Egress: in remote mode the extractor host joins the host set checked against the calling principal's `egress_ack` (loopback covered by `local`; embedded mode needs no entry). A refused stage sends nothing and is recorded on the file; other stages still run. Acceptance: with a remote extractor host missing from `egress_ack`, the fake extractor receives zero requests and the result names the host with `egress_not_acknowledged`.
- [ ] 1.5 Real-service test: `test/cli` (or a tagged `mcp/server` test) that runs xberg `v1.3.10` on loopback on a non-default port with its own cache, an embedded store and a local embedder, indexes one PDF, one DOCX and one CSV fixture by CID, and finds each by a phrase it contains. It skips with a named reason when `IPFS_MCP_TEST_XBERG` (path to the binary) is unset. Acceptance: the test exists, uses its own `IPFS_PATH` and non-default ports, and stops only the processes it started; it runs at `phase-integration-gate`.
- [ ] 1.6 Disabled states: with no `extractor` block no xberg process starts, no extractor request is made, and a PDF is skipped `mime_not_allowed` exactly as in G12; with an extractor but the MIME type absent from `policy.mime_allowlist`, the file is skipped `kind_not_enabled`. Acceptance: unit tests plus `TestMCPExtractorDisabled` in `test/cli/` exist.
- [ ] 1.7 No CID injection: extraction issues no `add`, `block/put`, `dag/put`, `pin/add`, `files/write` or `routing/provide` RPC call, and images xberg returns from documents are discarded. Acceptance: a test with the recording fake RPC asserts the call list after indexing a DOCX with an embedded image.
