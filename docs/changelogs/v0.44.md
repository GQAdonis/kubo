### Overview

### 🔦 Highlights

#### Experimental: `ipfs mcp` serves your node to AI agents

`ipfs mcp` is a [Model Context Protocol](https://modelcontextprotocol.io/specification) server for MCP clients such as Claude Code, Codex and OpenCode. It is a client of a running daemon's RPC API (Kubo 0.29.0 or newer, including stock Kubo and IPFS Desktop): it never opens the repo, adds no repo config key, and changes nothing in `/api/v0`, the gateway or the default CID recipe. It speaks MCP on stdio by default; `--http` serves Streamable HTTP on `127.0.0.1:5050` with bearer tokens and per-principal grants from a separate `--mcp-config` file. Every tool that changes something is confirmed by a person on every transport (MCP elicitation, else the macOS or Linux system prompt; the real-hardware check of that prompt and the IPFS Desktop confirmation window are still pending), and destructive tools are off by default. `--print-rpc-allowed-paths` prints a least-privilege `API.Authorizations` entry. See [`docs/mcp/user-guide.md`](../mcp/user-guide.md) and the [configuration reference](../mcp/config-reference.md).

To turn it off: do not run `ipfs mcp`; nothing starts by itself. Within it, `--read-only` removes every write tool, `--tools` drops groups, the HTTP listener stays off without `--http`, and `--confirm=none` turns the out-of-band prompts off (writes are then refused unless the client elicits). To remove the command from the binary: `make build GOTAGS=nomcp`.

#### Experimental: agent loop with AG-UI and A2A endpoints

With a model server you name (any OpenAI-compatible endpoint; there is no default), `ipfs mcp --http` can run a bounded agent loop and serve it to chat UIs over AG-UI (`--agui`, `POST /agui`) and to other agents over A2A 1.0 (`--a2a`, `POST /a2a` and `/.well-known/agent-card.json`). Callers are configured principals, read-only unless granted, and node content reaches the model only for hosts listed in the principal's `egress_ack`. A2A peers can never approve a change; a person approves on this machine. See [`docs/mcp/agentic.md`](../mcp/agentic.md).

To turn it off: it is off unless `--llm-base-url` and `--llm-model` (or the `llm` section) are set, and `/agui` and `/a2a` additionally need `--agui` / `--a2a`. To remove the code: `make build GOTAGS=noagent`.

#### Experimental: semantic search over your content

With an `embeddings` section in the `--mcp-config` file, `ipfs mcp` indexes text you add or name with an embedding model you choose and stores vectors in SurrealDB: a `surreal` binary you installed, supervised on loopback, or a remote server. Search results are read back from your node; vectors follow pins and `ipfs_index_reconcile` removes those of content unpinned elsewhere. Indexing never adds, pins or announces anything. See [`docs/mcp/embeddings.md`](../mcp/embeddings.md). The SurrealDB server is BSL 1.1 licensed; Kubo links none of its code.

To turn it off: it is off unless the config file has an `embeddings` section; remove the section and no process starts and the `ipfs_index_*` tools disappear. `"policy": {"auto": false}` (the default) indexes only on request.

#### Experimental (fork only): agent chat for the Web UI fork

> [!NOTE]
> This item describes a fork-only feature. Remove it before this changelog goes upstream: the chat ships in no upstream Web UI or IPFS Desktop release.

A chat sidebar for the Web UI that talks to `/agui`, with in-chat approval of writes and the system prompt for destructive calls, is built in the Web UI fork. It is **not** in the Web UI that this Kubo serves at `/webui`, and the IPFS Desktop pairing it needs is not delivered yet. See [`docs/mcp/chat-setup.md`](../mcp/chat-setup.md).

To turn it off: the chat is off by default in Web UI Settings, and switching it off loads nothing and removes the stored token; on the server, leave `--agui` unset.

#### Fork only: `/webui` opens the fork's Web UI build

> [!NOTE]
> This item describes a fork-only change. Remove it before this changelog goes upstream: upstream Kubo keeps pointing `/webui` at the upstream ipfs-webui release.

`http://127.0.0.1:5001/webui` now redirects to the Web UI build of the GQAdonis/ipfs-webui fork (CID `bafybeiblix77cfttmrmz5h54qacay5f4z5bgajc736ufiyoy5cus54stki`, built from fork commit `2be6b78c`), which registers the node's tools for browser agents (WebMCP) and carries the agent chat. This is a change to what the RPC listener's `/webui` shows, and nothing else: `/api/v0`, the HTTP gateway and the default CID recipe are unchanged, and no config key is added. The previous upstream build (v4.13.0) and every earlier build stay in the list the RPC listener serves, so their `/ipfs/<cid>/` paths still load.

The first visit fetches the build from the network, and a node can only do that once the CID is available from a peer. To turn it off, pick the honest option that fits: open an earlier build by its path (`http://127.0.0.1:5001/ipfs/bafybeiciqeyipumpmhxzlxnbqdbbv6u5uij4hy4wax64dmj7kvrhusiq6y/` is upstream v4.13.0); set `Gateway.NoFetch=true` and do not pin the build, so `/webui` answers `503` instead of fetching it; or build Kubo from upstream. There is no config key that makes `/webui` redirect to a different build.
