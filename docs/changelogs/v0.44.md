### Overview

### 🔦 Highlights

#### Experimental: `ipfs mcp` serves your node to AI agents

`ipfs mcp` is a [Model Context Protocol](https://modelcontextprotocol.io/specification) server for MCP clients such as Claude Code, Codex and OpenCode. It is a client of a running daemon's RPC API (Kubo 0.29.0 or newer, including stock Kubo and IPFS Desktop): it never opens the repo, adds no repo config key, and changes nothing in `/api/v0`, the gateway or the default CID recipe. It speaks MCP on stdio by default; `--http` serves Streamable HTTP on `127.0.0.1:5050` with bearer tokens and per-principal grants from a separate `--mcp-config` file. Every tool that changes something is confirmed by a person on every transport (MCP elicitation, else the macOS or Linux system prompt; the real-hardware check of that prompt and the IPFS Desktop confirmation window are still pending), and destructive tools are off by default. `--print-rpc-allowed-paths` prints a least-privilege `API.Authorizations` entry. See [`docs/mcp/user-guide.md`](../mcp/user-guide.md) and the [configuration reference](../mcp/config-reference.md).

To turn it off: do not run `ipfs mcp`; nothing starts by itself. Within it, `--read-only` removes every write tool, `--tools` drops groups, the HTTP listener stays off without `--http`, and `--confirm=none` turns the out-of-band prompts off (writes are then refused unless the client elicits). To remove the command from the binary: `make build GOTAGS=nomcp`.

#### Experimental: agent loop with AG-UI and A2A endpoints

With a model server you name (any OpenAI-compatible endpoint; there is no default), `ipfs mcp --http` can run a bounded agent loop and serve it to chat UIs over AG-UI (`--agui`, `POST /agui`) and to other agents over A2A 1.0 (`--a2a`, `POST /a2a` and `/.well-known/agent-card.json`). Callers are configured principals, read-only unless granted, and node content reaches the model only for hosts listed in the principal's `egress_ack`. A2A peers can never approve a change; a person approves on this machine. See [`docs/mcp/agentic.md`](../mcp/agentic.md).

`ipfs mcp` connects to each model, embedder, vector store, extractor and describer host directly, at the host you configured and acknowledged (`egress_ack`); it does not route prompts, document text or API keys through `HTTP_PROXY`, `HTTPS_PROXY` or `NO_PROXY`. If you need a proxy in front of such an endpoint, point the configured URL at a gateway host you control (see `docs/environment-variables.md`). Only the RPC client for a remote `--api` URL honours the variables.

To turn it off: it is off unless `--llm-base-url` and `--llm-model` (or the `llm` section) are set, and `/agui` and `/a2a` additionally need `--agui` / `--a2a`. To remove the code: `make build GOTAGS=noagent`.

#### Experimental: semantic search over your content

With an `embeddings` section in the `--mcp-config` file, `ipfs mcp` indexes text you add or name with an embedding model you choose and stores vectors in SurrealDB: a `surreal` binary you installed, supervised on loopback, or a remote server. Search results are read back from your node; vectors follow pins and `ipfs_index_reconcile` removes those of content unpinned elsewhere. Indexing never adds, pins or announces anything. See [`docs/mcp/embeddings.md`](../mcp/embeddings.md). The SurrealDB server is BSL 1.1 licensed; Kubo links none of its code.

To turn it off: it is off unless the config file has an `embeddings` section; remove the section and no process starts and the `ipfs_index_*` tools disappear. `"policy": {"auto": false}` (the default) indexes only on request.

#### Experimental: whole-node vector search

Building on the semantic search above, `ipfs mcp` can index every file type on the node, not just plain text and Markdown: documents, code and data files go through an operator-configured [xberg](https://github.com/Know-Me-Tools/xberg) extractor (a supervised binary you installed, or a remote service; xberg is never linked into Kubo), and images and videos become searchable through text descriptions from any OpenAI-compatible chat model you point at (there is no default). Three operator-started, confirmed and capped tools (`ipfs_index_bulk_start`, `ipfs_index_bulk_status`, `ipfs_index_bulk_cancel`) walk your recursive pins and MFS with offline reads only: a run never fetches from the network and indexing adds, pins and announces nothing. `POST /index/search` and `GET /index/status` on the `ipfs mcp --http` listener serve the Web UI search page under the same principal and `egress_ack` rules as the tools. See [`docs/mcp/embeddings.md`](../mcp/embeddings.md) and [ADR-0011](../mcp/0011-whole-node-vector-search.md). `ipfs mcp` now starts when the search services are down and reports them in index status.

Egress: describing a file sends its bytes to the describer host, and a remote extractor or embedder receives content the same way; every non-loopback host must be listed in the principal's `egress_ack` before any request is built, and a hosted describer such as Xiaomi's MiMo is never a default. Media go to the describer as bytes in the request, never as a gateway URL.

`ipfs mcp` connects to each model, embedder, vector store, extractor and describer host directly, at the host you configured and acknowledged (`egress_ack`); it does not route prompts, document text or API keys through `HTTP_PROXY`, `HTTPS_PROXY` or `NO_PROXY`. If you need a proxy in front of such an endpoint, point the configured URL at a gateway host you control (see `docs/environment-variables.md`). Only the RPC client for a remote `--api` URL honours the variables.

To turn it off: remove the `extractor` and `describer` blocks from the `embeddings` section (indexing then covers only `text/plain` and `text/markdown`, as before); set `"bulk": {"enabled": false}` and the three bulk tools are not listed; set `"search_route": {"enabled": false}` and `/index/search` and `/index/status` answer 404.

Inside a cluster, `embeddings.insecure_http_hosts` lets the operator name the in-cluster hosts (for example `ipfs-xberg.ipfs.svc:8000`) that may be reached over plain `http`; the default `[]` is the off switch (plain `http` to a non-loopback extractor, describer, keyed embedder or credentialed store stays refused at startup), and `egress_ack` is still required for every listed host.

The same list governs the agent model backend set through the settings API (a plain `http` backend URL is accepted only for loopback or a listed host, and a scheme change needs the host confirmation), and the settings route now answers CORS only for the origins in `agent.origin_allowlist`: add the console origin there if you relied on `http.allowed_origins`. Unpinning a directory through `ipfs mcp` now also drops the search entries of the files inside it that no other pin or MFS file covers. Search stays off, as before, unless the `embeddings` section is present.

#### Experimental (fork only): agent chat for the Web UI fork

> [!NOTE]
> This item describes a fork-only feature. Remove it before this changelog goes upstream: the chat ships in no upstream Web UI or IPFS Desktop release.

A chat sidebar for the Web UI that talks to `/agui`, with in-chat approval of writes and the system prompt for destructive calls, is built in the Web UI fork. It is **not** in the Web UI that this Kubo serves at `/webui`, and the IPFS Desktop pairing it needs is not delivered yet. See [`docs/mcp/chat-setup.md`](../mcp/chat-setup.md).

To turn it off: switch **Enable agent chat** off in Web UI Settings (it ships on in the fork, see the next entries), which loads nothing and removes the stored token; on the server, leave `--agui` unset.

#### Fork only: `/webui` opens the fork's Web UI build

> [!NOTE]
> This item describes a fork-only change. Remove it before this changelog goes upstream: upstream Kubo keeps pointing `/webui` at the upstream ipfs-webui release.

`http://127.0.0.1:5001/webui` now redirects to the Web UI build of the GQAdonis/ipfs-webui fork (CID `bafybeiblix77cfttmrmz5h54qacay5f4z5bgajc736ufiyoy5cus54stki`, built from fork commit `2be6b78c`), which registers the node's tools for browser agents (WebMCP) and carries the agent chat. This is a change to what the RPC listener's `/webui` shows, and nothing else: `/api/v0`, the HTTP gateway and the default CID recipe are unchanged, and no config key is added. The previous upstream build (v4.13.0) and every earlier build stay in the list the RPC listener serves, so their `/ipfs/<cid>/` paths still load.

The first visit fetches the build from the network, and a node can only do that once the CID is available from a peer. To turn it off, pick the honest option that fits: open an earlier build by its path (`http://127.0.0.1:5001/ipfs/bafybeiciqeyipumpmhxzlxnbqdbbv6u5uij4hy4wax64dmj7kvrhusiq6y/` is upstream v4.13.0); set `Gateway.NoFetch=true` and do not pin the build, so `/webui` answers `503` instead of fetching it; or build Kubo from upstream. There is no config key that makes `/webui` redirect to a different build.

#### Fork only: agent features ship enabled, each with an off switch

> [!NOTE]
> This item describes a fork-only change. Remove it before this changelog goes upstream: stock Kubo and upstream `ipfs mcp` defaults are unchanged (no HTTP listener, no `/agui`, no settings route without flags and an `admin` principal).

In this fork the agent features that are its purpose are on by default, so a fresh IPFS Desktop and the fork's Web UI work as an agent client without setup. Nothing here enables a third-party service: there is no default model, embedder, extractor or describer endpoint, and every write and destructive tool still waits for your confirmation. A default-on migration fills only settings that are absent; a value you stored as `false` is kept. The full table, with each feature's disabled-state test, is in [`docs/mcp/config-reference.md`](../mcp/config-reference.md#features-enabled-by-default-in-this-fork) and [`docs/mcp/chat-setup.md`](../mcp/chat-setup.md#defaults-in-this-fork).

What is on, and how to turn each off:

- **Local `ipfs mcp` endpoint (IPFS Desktop).** Desktop starts `ipfs mcp --http --agui` on `127.0.0.1` (port 5050 preferred). Off: the tray toggle, or set `mcpSidecar.enabled` to `false` in the Desktop store.
- **Web UI agent chat.** Off: Web UI Settings, Agent chat, switch **Enable agent chat** off. In the Desktop store: `agentChat.enabled` = `false`.
- **WebMCP tools in the Web UI.** Off: Settings, WebMCP, switch `enabled` off (local storage key `ipfs-webui:webmcp`). Write tools are not part of this: `writes` stays off on every page load.
- **Desktop confirmation window** (macOS and Linux; never Windows). Off: `desktopConfirm.enabled` = `false`, or the tray "Turn off" entry.
- **Desktop settings bridge.** Off: `agentSettings.enabled` = `false` in the Desktop store.
- **Settings API.** `agent.settings.enabled` defaults to `true` but the route exists only when an `admin` principal is configured. Off: in the `--mcp-config` file, `{"agent": {"settings": {"enabled": false}}}` makes the route answer 404, or configure no `admin` principal.
- **Server-emitted A2UI surfaces on `/agui`.** `agent.a2ui` defaults to `true`. Off: `{"agent": {"a2ui": false}}` in the `--mcp-config` file; the run stream is otherwise unchanged and the chat shows its plain tool-call card.

Resource use: the `ipfs mcp` child that Desktop supervises used about 41 MiB of resident memory idle (one macOS arm64 machine, no model backend configured, no chat run; use under load is higher and was not measured). Nothing indexes, embeds or calls a model until you configure it.

To remove the code from the binary: `make build GOTAGS=noagent`.
