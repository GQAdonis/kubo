## 6. go.mod and the transitive-bump rule: met by an operator-ruled exception

- go-jose v4.1.6 reaches the build through p2p-forge, which is a protected stack, via a committed fork `replace` in all three modules, not through an upstream release. The direct `require github.com/go-jose/go-jose/v4 v4.1.6` (`go.mod:102`) is consistent with the fork's own requirement, so MVS does not select a version ahead of the stack actually used.
- The rule's normal order (upstream PR, green CI, release, then bump) was not followed. The operator approved the exception in writing (`docs/mcp/0013-console-session-auth.md:187`; gotcha `.prometheus/gotchas.md:26`).
- The three modules moved together, as the diffs show.
- Remaining items are in MAJOR-1: the changelog disclosure, and the requirement that the eventual upstream release needs go-jose >= v4.1.6 before the replace is dropped.
- I could not verify the fork commit `d40b57a`'s diff against p2p-forge v0.10.1. p2p-forge is the AutoTLS client, so a change there beyond go-jose could affect AutoTLS registration behavior.

## 7. Verifier code quality

Strengths, each read directly:

- **Algorithms:** `jwt.ParseSigned` is called with the configured algorithm list (`jwt.go:176`). HS* and `none` are refused at config load (`oidc_config.go:77-82`, `150-166`) and again by schema enum.
- **Key/algorithm binding:** a key's own `alg` is enforced (`jwt.go:193`).
- **Claims:** `sub` and `exp` are required (`jwt.go:200`). Issuer is exact, audience is any-of, and leeway applies (`jwt.go:203-214`).
- **Size bounds:** tokens up to 16 KiB (`jwt.go:24`), JWKS bodies up to 1 MiB, only public `sig` keys that carry a `kid` (`jwks.go:161-170`), and no redirects (`jwks.go:57`).
- **Refetch limit:** at most once per 30 s, with stale keys still served while the issuer is down (`jwks.go:83-95`).
- **Errors:** the error returned to the caller is uniform and reveals nothing about which check failed (`jwt.go:41`, `227-230`).
- **Route checked first:** the route is checked before any key fetch (`jwt.go:241-244`).
- **Principal mapping:** `sub` only, never email (`jwt_session.go:164-176`). A duplicate subject within one kind is rejected both in config (`principals.go:404-428`) and in the verifier (`jwt_session.go:144-160`).
- **Step-up:** enforced on every route except the session report (`jwt_session.go:187-192`). A missing `auth_time` fails wherever a bound applies (`jwt_session.go:38-41`).
- **Static tokens unchanged:** the chain tries the constant-time static match first and passes a token to the JWT verifier only when it is shaped like a JWS (`auth_chain.go:30-39`).
- **Go style:** errors are wrapped with `%w` (`jwks.go:144-162`), with early returns and `slices` helpers per AGENTS.md.
- **Test coverage:** the 2.1 acceptance cases are all present, plus extra cases: no audience, no `exp` or `sub`, no `kid`, tampered signature, oversized token, opaque token, and expiry inside and outside the skew (`mcp/server/jwt_test.go:59-90`). Redaction has its own test (`jwt_redaction_test.go:21`).

Gaps are listed above: MINOR-4 (fetch cancelled by the request context), MINOR-5 (untested JWKS safeguards), MINOR-6 (startup message), NIT-1 (discarded encode error).
