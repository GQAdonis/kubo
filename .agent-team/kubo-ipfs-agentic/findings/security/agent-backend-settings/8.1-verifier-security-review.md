# 8.1 Security review: `ipfs mcp` OIDC verifier (tasks 2.x) and contract (1.2, 1.3)

Reviewer: kubo-ipfs-agentic security-reviewer. This was an independent review in a separate context from the builders, done by reading code only (Read, Glob and Grep). I ran no tests and did not touch the cluster.

Scope read in full: `mcp/server/jwt.go`, `jwks.go`, `jwt_session.go`, `oidc_config.go`, `auth_chain.go`, `auth_session.go`, `auth.go`, `http.go`, `principals.go`, `access.go` (lines 1-200), `access_identity.go`, and the auth parts of `config.go` (150-370). Also `cmd/ipfs/kubo/mcp_http.go`, the auth.oidc and principals sections of the contract schema (`ipfs-mcp-config.schema.json`:270-514), `routes/session.json` and `examples/oidc-session.json`, ADR-0013 sections 3-11 (:150-249), `tasks.md` 1.3 and 2.x, `test/cli/mcp_session_token_test.go`:95-175, the test lists of the verifier `_test.go` files, `jwt_test.go`:1-180, and the go-sdk v1.8.0 `auth/auth.go` the listener depends on.

Verdict: there is no open CRITICAL or HIGH. The verifier fails closed on every path I traced. The LOW items are gates to clear before `lke-agent-settings` opens `/agui` or settings to JWT identities. None of them is exploitable in the deployed `routes: [session]` configuration.

## Checked and sound

- **Algorithm confusion.**
  - The config accepts only asymmetric algorithms (`oidc_config.go`:77-82, :150-166; schema enum :413-424).
  - `jwt.ParseSigned` is called with the configured list, so `none` and `HS*` fail before any key lookup (`jwt.go`:176).
  - The header `alg` is re-checked (`jwt.go`:181).
  - A JWK that names an `alg` must match the header (`jwt.go`:193).
  - A kty/alg mismatch fails inside go-jose verify (`jwt.go`:197).
  - Tests cover HS256 signed with the public JWK, `alg: none` with and without a signature, and a PS256-only key used for RS256 (`jwt_test.go`:75-77, :144-155).
- **kid handling.**
  - A missing `kid` is refused (`jwt.go`:181).
  - An unknown `kid` returns `errNoSuchKey`, which becomes 401 (`jwt.go`:186-187; `jwks.go`:97-100).
  - A refetch happens at most once per 30 s whatever the outcome (`jwks.go`:21, :83-88, :136-138).
  - Concurrent misses share one fetch (`jwks.go`:74-79).
  - `jku`, `x5u` and an embedded `jwk` are never used. The key comes only from the configured URL (`jwks.go`:31-35, `jwt.go`:197).
- **JWKS fetch.**
  - 10 s client and context timeout (`jwks.go`:23, :54, :140).
  - Redirects are not followed; a 3xx becomes a non-200 error (`jwks.go`:57, :157-159).
  - The body is capped at 1 MiB (`jwks.go`:25, :161).
  - Only public signing keys that have a `kid` are kept (`jwks.go`:165-170).
  - An empty set is an error (`jwks.go`:171-173).
  - Errors carry the URL with userinfo removed and never the body (`jwks.go`:144-162, :181-187).
  - The cache TTL defaults to 15m and must be positive (`oidc_config.go`:103-108).
  - An issuer outage gives 401, not 500 (`jwt.go`:188-190), and never stops startup (`http.go`:541-554; `mcp_http.go`:257-268).
- **Claims.**
  - `sub` and `exp` are required (`jwt.go`:200-202).
  - `iss` must match exactly, and `aud` must match at least one configured value (`jwt.go`:203-207).
  - `exp`, `nbf` and a future `iat` are checked with leeway (`jwt.go`:208-214).
  - Skew is capped at 2m (`oidc_config.go`:100-102).
  - The middleware applies the same skew to the verdict expiry (`http.go`:186-195; go-sdk `auth.go`:170).
  - The issuer must be https (schema :376). jwks_url must be https, or http only on loopback (schema :401; `oidc_config.go`:168-183).
- **Subject mapping.**
  - Principals are selected by exact `sub` only. Email never selects one (`jwt_session.go`:162-176; test `jwt_session_test.go`:11).
  - A subject listed twice within one kind is rejected at load (`principals.go`:404-429) and again in the verifier (`jwt_session.go`:144-160).
  - Only the kinds ui, human-mcp and admin can carry subjects (`principals.go`:412-414; `jwt_session.go`:138-140).
  - Session principals use the same `configuredIdentity` as static bearers, so grants, egress_ack and policy are identical (`principals.go`:344-364, :446-466; `config.go`:336-339).
  - Admin principals get read scope only and no tool groups (`principals.go`:346-351).
- **Step-up.**
  - The admin defaults are a second-factor `amr` and an `auth_time` within 1h (`jwt_session.go`:27-29; `principals.go`:453-455).
  - A missing or future `auth_time` fails (`jwt_session.go`:34-44).
  - The rule is enforced on every route except the session report, which only reports it (`jwt_session.go`:187-192).
- **Route scoping.**
  - A JWT is refused with 401 on any route `auth.oidc.routes` does not list, before any key fetch (`jwt.go`:237-244).
  - Path classification only matches exact paths or slash-delimited prefixes (`jwt_session.go`:93-110).
  - The mount's kind gate applies on top of it (`http.go`:428-441).
  - With the deployed `routes: [session]`, a session token on `/mcp`, `/agui` or settings is 401. The CLI test checks the `/mcp` case (`test/cli/mcp_session_token_test.go`:117-118).
- **Denials cannot leak through.** A `Denial` travels as a placeholder TokenInfo, and the kind gate answers it before any handler runs (`auth.go`:57-68; `http.go`:430-434). Every non-public mount goes through `authenticate` (`http.go`:314-317).
- **Origin.**
  - `require_origin` defaults to true (`oidc_config.go`:116).
  - Non-safe methods need an `Origin` listed in `agent.origin_allowlist`. A missing Origin is refused (`jwt.go`:264-277).
  - Listed origins are normalized and `null` is rejected (`http.go`:235-246).
  - `/auth/session` uses strict CORS limited to that list, with no credentials header (`http.go`:212-221, :309-346, :404-413).
  - Cross-site fetch metadata is refused unless the origin is listed (`http.go`:369-375).
- **Token sources.** Only the `Authorization: Bearer` header is read (go-sdk `auth/auth.go`:129-133). There is no query or cookie path, and `ipfs mcp` never reads cookies (ADR-0013:214).
- **Static and JWT separation.**
  - The static verifier runs first, with a constant-time digest compare (`auth.go`:197-209; `auth_chain.go`:30-39).
  - Only JWS-shaped tokens reach the JWT path (`jwt.go`:151-167).
  - A static bearer on `/auth/session` gets 401 "no session" (`auth_session.go`:49-53).
  - Static bearers are never subject to Origin or step-up checks (`jwt_stepup_test.go`:89; `mcp_session_token_test.go`:123-124).
- **Error responses.**
  - Every token refusal returns one generic error (`jwt.go`:41, :227-230).
  - The specific reason is logged only at Debug level.
  - Denials name no token detail (`http.go`:465-472).
  - The session report sets `Cache-Control: no-store` and returns no `sub` (`auth_session.go`:54-64; `mcp_session_token_test.go`:144).
- **Logging.** No token is ever logged (`jwt.go`:76-77, :189; `jwt_redaction_test.go`:21; `mcp_session_token_test.go`:145).
- **Off switch.**
  - With `auth.oidc.enabled` false, `OIDCSettings` is nil and the verifier is static only (`principals.go`:433-442; `mcp_http.go`:238-256).
  - `/auth/session` is not mounted (`http.go`:212).
  - Nothing is fetched (`mcp_http_oidc_test.go`:39; `mcp_session_token_test.go`:148-173).
  - Values are still validated while the switch is off (`oidc_config.go`:87-90).
- **No anonymous fallback.** A configuration that has only session principals does not become anonymous (`mcp_http.go`:219-224, :242-248).

RCE vectors: SSRF is SAFE. The JWKS URL comes only from config, is https-only, follows no redirects, and is never derived from a token (`jwks.go`:31-35, :57). Command injection, eval, SSTI and path traversal are N/A: there is no such sink in the verifier. Deserialization is SAFE: `encoding/json` with a size cap (`jwks.go`:161) and a 16 KiB token cap (`jwt.go`:24). Dependency hijacking: see INFO-4.

## Before `lke-agent-settings` exposes `/agui` or settings to JWT identities

1. Fix or rule on LOW-1 (azp and single-`aud`) and LOW-2 (staleness cap).
2. Fix LOW-3, or keep one subject per write-granted principal.
3. Set `auth.oidc.routes` explicitly and set `agent.origin_allowlist` to exactly `https://console.prometheusags.ai` (LOW-4).
4. Add the LOW-5 tests.
5. Carried, outside this code: MEDIUM-3 (Kratos cookie scope) means the `ui` principal has no step-up. Consider `require_amr` on `console-ui` once a second factor is enabled.

## Not verified here

- That the tests pass. I ran nothing: no `go test ./mcp/server/...`, no `make build`, and no `go test ./test/cli/... -run TestMCPSessionToken`. Task 2.x acceptance results are taken from `tasks.md` and were not observed.
- go-jose v4.1.6 behaviour I relied on but did not read in source: rejecting a kty/alg mismatch at verify, rejecting unsupported `crit`, ignoring an embedded `jwk`/`jku`, and RSA minimum key size.
- Deployed state: the actual sidecar config (`routes`, `require_origin`, `agent.origin_allowlist`, subjects), and that commit 1140ff10c / image sha256:3467dea8 matches the reviewed tree.
- Hydra: that `strategies.access_token` is still `opaque`, and that no Hydra client has `ipfs-console` in its allowed audiences. LOW-1's reachability depends on both.
- Envoy: that it overwrites a client-supplied `Authorization` on `/auth/session`, that its JWT and RBAC filters run before the backend, and whether the gateway host (`ipfs.prometheusags.ai`) routes any path other than `/mcp` (for example `/auth/session`) to `ipfs-mcp:5050` without the session policy.
- That the NetworkPolicy blocks direct in-cluster access to `ipfs-mcp:5050`. ADR-0013 section 8 states the design; I saw no probe output.
- That the Web UI renders `email` as text (INFO-3).
