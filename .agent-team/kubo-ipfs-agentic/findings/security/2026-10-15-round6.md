# Security review: agent-backend-settings Round 6

Reviewer: `security-reviewer` (Claude Opus, independent context, read-only). Date: 2026-10-15. Static reading of the uncommitted Round 6 set in kubo, ipfs-desktop and ipfs-webui; no tests, Electron, Touch ID, dialog or browser run. Written to disk by the lead.

**Verdict: FAIL** (H1). API-stored key path, Desktop key path, probe scope, proxy change, Desktop Search and default-on migration hold. Other findings: L1-L3 LOW, L4 LOW/INFO, I1-I4 INFO.

**Operator ruling after this review (2026-10-15):** for H1 the operator chose "Let it follow, document it" — a key supplied by reference follows a backend host move. Per the reviewer, H1 then drops to LOW once the Web UI copy, the D4 server text and the docs say so plainly; ADR-0012 is amended and the LKE case recorded as an accepted residual.

## Findings

- **H1 HIGH (LOW after the ruling): a referenced key follows a host move, and the Web UI says it does not.** `mcp/server/settings.go:531-546` withholds only `APIKey.File == st.keyFilePath()`; a reference (env, file, `--llm-api-key-*`) is applied to the new `BaseURL` (`:621-622`), attached by `LLMClient` (`llm_client.go:129-137`) and by `probeKey` once the host is current (`settings_probe.go:145-157`); `TestSettingsMoveKeepsReferencedKey` (`settings_keymove_test.go:99-106`) pins it. Web UI: `public/locales/en/agentSettings.json:192` (`confirm.serverManaged.text`, shown by `ConfirmHost.js:59-61` at the move) says the server-set key "does not follow a host change"; `:189` (`helpKey`, shown for any `set:true` key per `form.js:203`) says the stored key does not follow; `docs/mcp/agentic.md:97` says a provider change on an `accept_secrets: false` node is a config edit. ADR-0012 contradicts itself (`:28`, `:53`, `:72` vs `:76`, `:83-84`). LKE scenario: a mistyped provider host after Apply receives the mounted cloud key on every chat and probe. Fix chosen (alternative): correct `agentSettings.json:189`, `:192`, `agentic.md:97`, `chat-setup.md:44`, and make the D4 server text (`settings.go:578-581`) and the confirmation copy name the key when it is a reference.
- **L1 LOW: `probeKey` reads the key and the current backend under two locks** (`settings_probe.go:145-157`, `storedKey` `:225-242`); a concurrent move-and-clear can let one probe send the old key to the new host. Fix: read key and `current` in one critical section.
- **L2 LOW: Search confirmation without Touch ID shows agent-backend copy and parents to the Web UI window** (`ipfs-desktop/src/webui/index.js:300-309`, `:322-326`; `search/service.js:140`; `confirm/native-dialog.js:20-29`; `en.json:391-398`); `docs/agent/SEARCH.md:49-51` claims the prompt names what goes there. Fix: pass a purpose through `hostConfirm.confirm`, Search-specific strings, parent to the requesting window.
- **L3 LOW: Web UI Search off switch built but not mounted or documented** (`src/search/settings-store.js:8-13`; `SearchSettingsSwitch.js` only in a test; route `src/bundles/routes.js:23`). Fix: mount next to the chat switch; document the key and the server-side switch.
- **L4 LOW/INFO: Search binaries get no ownership or writability check** (`mcp-sidecar-search.js:191-212`; xberg loads dylibs from its directory per `SEARCH.md:12-13`). Fix: refuse or warn when the binary or its directory is not owned by the user/root or is group/other-writable.
- **I1:** a declined Search host stays refused until the Web UI window is recreated (`host-confirm.js:27-29`; `webui/index.js:242-243`, `:412-413`) though the copy says reopen this window (`en.json:385`; `SEARCH.md:52`). Clear on Search window close or reword.
- **I2:** Desktop deletes the key before the PUT (`settings-service.js:429-435`); fails safe; consider restoring on failure or saying the key was removed.
- **I3:** stale proxy comment (`mcp-sidecar.js:166-169`).
- **I4:** `plain-text.js:7-10` does not strip zero-width (U+200B-200D, U+FEFF) or tag characters (U+E0000-E007F); consider it.

## Accepted residuals

## Verified controls

ADR-0012 API-stored key: move clears and reports `key_not_carried` (`settings.go:527-546`, `:592-613`), unparsable URL counts as moved, default ports normalised (`:651-672`), path/model change not a move, `api_key` in the write wins, moving back does not restore (tests `settings_keymove_test.go:61-153`). Option A: `probeKey` no longer uses `egress_ack`/`local` (`settings_probe.go:139-157`); key never from the request; candidate https or loopback http without userinfo/query/fragment; no redirects; echoed key scrubbed. Desktop: origin comparison (`settings-service.js:380-386`), key cleared only after confirmation and sidecar restarted before the PUT, `key_not_carried` whitelisted. Web UI: `read-shape.js:21-30`, `ApplyStatus.js:44-54`, `form.js:294` (copy wrong for referenced keys, H1). Contract `KeyNotCarried` additive. Proxy: `Proxy=nil` for embedder, store, extractor and its proxy upstream, describer, LLM client, probe; only the remote `--api` RPC client honours proxies; documented. Desktop Search: off by default; no PATH lookup or download; `allow_model_downloads:false`; 0700 owned dirs; https or loopback http without credentials; `egress_ack` local plus confirmed hosts; Search window sandboxed with its own partition, CSP `connect-src 'none'`, IPC sender checks; restart race fixed. `mime_allowlist` acceptable (bulk runs are confirmed writes); note native parsers handle third-party PDFs/Office. Default-on migrations only fill absent keys; WebMCP writes never stored. Search results type-checked, plain text, CID regex before links, token in header only with `credentials:'omit'`. Bulk offline; widening capped. Stock defaults test.
