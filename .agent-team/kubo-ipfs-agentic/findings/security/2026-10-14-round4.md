# Security findings: agent-backend-settings Round 4

Reviewer: `security-reviewer` (Claude Opus, separate context that did not build the code). Date: 2026-10-14. Method: static reading only; no tests or binaries run. Written to disk by the lead from the reviewer's returned report (the reviewer's tools were read-only). B1 confirmed by the lead at `ipfs-desktop/src/daemon/mcp-sidecar.js:319-320`.

**Verdict: FAIL** (B1). Change A (`mcp-content-extractor`) alone: PASS WITH FINDINGS. Change B (`desktop-mcp-sidecar`): FAIL until B1 is fixed.

## Threat model delta

- New process: embedded xberg, started by `ipfs mcp` from an absolute path, bound to `127.0.0.1` on an ephemeral port, no authentication of its own. `/extract` accepts `files`, `urls` (fetches a URL) and `inputs` (server-side paths, off by default).
- New egress: a remote xberg, gated by the caller's `egress_ack`.
- New stored data: extracted, OCR and transcript text stored next to the vector (embedded store or remote SurrealDB).
- New Desktop child: `ipfs mcp`, with `desktop-ui` and `desktop-admin` bearer tokens in safeStorage passed by environment variable; loopback listener preferring 5050.

## A. mcp-content-extractor (kubo)

### A1. MEDIUM: the embedded xberg can be driven from a browser (cross-origin simple requests, DNS rebinding)

- Evidence: `mcp/server/embeddings/extractor_supervisor.go:191-211` (only `XBERG_CORS_ORIGINS`), `:215` (no credential); task 1.1 evidence README `:47-50`, `:114-119`.
- Scenario: a multipart POST is a CORS simple request; any page can POST `/extract` with `urls=[...]` or large uploads to the scanned port. CORS blocks reading, not executing. DNS rebinding makes it same-origin (no Host check). Impact: blind SSRF from the operator's machine (RFC1918 and link-local blocking unverified), CPU-heavy OCR, `DELETE /cache/clear`. Conflicts with "Never appropriate the machine's resources".
- Fix: in-process loopback reverse proxy with a per-start random bearer token and a `Host == 127.0.0.1:<port>` check, forwarding only `POST /extract` with `files`, `output_format`, `config`. Alternatives: Unix socket, or an xberg auth option if one exists. At minimum document the residual risk in `docs/config.md`.

### A2. MEDIUM: derived text outlives the content it came from

- Evidence: `mcp/server/index.go:187-196` returns stored `h.Text` without a presence check; native hits re-read offline and drop (`:197-209`); `service.go:216-218` stores the text; cleanup only through `ipfs mcp` unpin/GC or `ipfs_index_reconcile`.
- Scenario: `ipfs pin rm` + `ipfs repo gc` outside `ipfs mcp`; the full extracted text stays searchable by every principal with the `index` group indefinitely.
- Fix: offline presence check (`block/stat` or `files/stat` with `offline: true`) before returning a derived hit; drop it and queue `DeleteCID` or warn. Test that removes content outside `ipfs mcp`.

### A3. MEDIUM: extracted text bypasses `policy.max_bytes`

- Evidence: `extractor.go:41` (`maxExtractedText = 32 MiB`), `index.go:282-285` (read limit raised to `extractor.max_bytes`, up to 100 MiB), `index.go:400` (whole Markdown chunked); buffers at `index.go:307-311`, `extractor.go:364-391`, `:350`.
- Scenario: one confirmed `ipfs_index_cid` yields ~16,700 chunks (~1,050 embedder requests) at default `chunk_chars`; native ceiling is ~500 chunks. Unannounced paid-embedder cost; ~300 MB peak memory.
- Fix: cap derived text (`policy.max_bytes` or a documented `extractor.max_text_bytes` near the native ceiling) with `too_large` or truncation plus warning; cap chunks per document; stream the multipart body with `io.Pipe`.

### A4. LOW (investigate): Hugging Face endpoint not configurable; xberg telemetry unverified

- Evidence: `extractor_supervisor.go:191-210`, `supervisor.go:317-325` strip `HF_ENDPOINT` and any opt-out variables.
- Fix: pass through `HF_ENDPOINT` (or a config key); set `DO_NOT_TRACK=1`; record a network capture of an extraction run.

### A5. LOW: health check accepts any responder on the chosen port

- Evidence: `extractor_supervisor.go:171-184`, `:269-280`; pick-close-bind race `supervisor.go:273-288`.
- Fix: require `/health` to report the expected version; treat `s.exited` as failure after a healthy tick; prefer binding port 0 and reading the bound address.

### A6. LOW: existing `cache_dir` not checked for ownership or mode

- Evidence: `extractor_supervisor.go:73` (`MkdirAll` 0700 only on create); config `:80`, state `:243`, working dir `:216`.
- Fix: refuse a group- or world-writable `cache_dir`, or one not owned by the current user.

### A7. LOW: remote extractor over plain http to a non-loopback host accepted without a credential

- Evidence: `extractor.go:154`.
- Fix: require https for non-loopback, or at least warn at start (the embedder too).

### A8. LOW: a remote store now receives plaintext document text

- Evidence: `service.go:216-218`, `store.go:59`, `:203`.
- Fix: say so in `docs/config.md` and in the `egress_not_acknowledged` message; consider keeping derived text out of a remote store.

### A9. LOW: contract text no longer matches behaviour

- Evidence: `mcp/contract/catalog.json:1272` ("respects the MIME allowlist and size cap") vs `index.go:278-285`.
- Fix: update the description.

### A10. INFO: version check is self-reported, lower bound only

- Evidence: `extractor_supervisor.go:131-155`.
- Fix (optional): `xberg_sha256` pin; re-verify CORS and local-URI behaviour before accepting a new minor version.

### Verified controls (A)

No PATH lookup for xberg (`extractor.go:129`; watchdog still resolves `sh`/`ps` as before); version check present; environment allowlist (`XBERG_API_ALLOW_LOCAL_URI_INPUTS`, `XBERG_LLM_*` never inherited); loopback bind; reaping by command line plus watchdog; `urls`/`inputs` never sent; redirects blocked; response size caps; UTF-8 and NUL checks; extractor error text cleaned, capped and kept out of tool output; remote egress check before any I/O; Hugging Face downloads off by default; no silent CID injection (`cat` and `files/stat` only, test bans add/put/pin/provide); credential only in the Authorization header. Cross-principal reads of indexed text: accepted (pre-existing for native text; A2 widens it in time).

## B. desktop-mcp-sidecar (ipfs-desktop)

### B1. HIGH: principal tokens and the LLM key are never passed to the child

- Evidence: `src/daemon/mcp-sidecar.js:300-308` builds `secretEnv`; `:320` spawns with `env: { ...process.env, IPFS_PATH: repoPath, ...extraEnv }`.
- Scenario: `ipfs mcp` fails to read `{env: IPFS_MCP_DESKTOP_UI_TOKEN}` (`kubo/mcp/server/auth.go:95-97`) and exits; the sidecar restarts it every 1-30 s forever. Fails closed but the feature never works. If Desktop inherits `IPFS_MCP_DESKTOP_*_TOKEN` from its launcher, that external value becomes the principal token. The spec's token-flow assertions (`test/unit/mcp-sidecar.spec.js:317-321`, `:349-354`, `:365`) should fail against this code.
- Fix: `{ ...inheritedEnvWithoutSidecarNames, IPFS_PATH: repoPath, ...extraEnv, ...secretEnv }`, deleting the `SIDECAR_ENV` names from the inherited copy and spreading `secretEnv` last. Run the spec.

### B2. MEDIUM: port fixed after one probe, never rediscovered on restart

- Evidence: `mcp-sidecar.js:190-195` (probe then close), `:263`, `:273`, `:369`.
- Scenario: another local process binds 5050 between probe and spawn or after a crash; the child restart-loops on the occupied port while the squatter receives what clients send there, possibly the `desktop-ui` token.
- Fix: rediscover on restart or after N bind failures; have the child report its bound address (stderr line or a 0600 state file in `settingsDir`) and clients use only that; consider verifying the listener before sending the token.

### B3. LOW: full Desktop environment inherited by `ipfs mcp`

- Evidence: `:320`. Fix: allowlist (`PATH`, `HOME`, `TMPDIR`, `IPFS_PATH`, locale, sidecar names).

### B4. LOW: child stderr logged verbatim with an unbounded buffer

- Evidence: `:333-349`. Fix: cap `errBuf` (64 KiB) and per-line length.

### Verified controls (B)

Tokens from `crypto.randomBytes(32)` base64url; safeStorage only, Linux `basic_text`/`unknown` treated as unavailable, fails closed without a keystore; no plaintext in electron-store; config holds env var names only, 0600 in a 0700 dir; LLM key by env name, logged by name only; loopback only; kill by tracked PID only; off switch `mcpSidecar.enabled` default on (allowed for this fork feature), applied at runtime, not started for a remote daemon; `desktop-ui` writes behind confirmation; `egress_ack: ['local']`; no analytics.
