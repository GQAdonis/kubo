## 2026-10-09
- Initialized by prometheus-context-bootstrap.

- 2026-10-09: A subagent copied `pkill -f "ipfs daemon"` from AGENTS.md during test/cli runs. That kills every daemon by name, including the operator's IPFS Desktop daemon on default ports. Never use it here; stop only harness daemons by PID. Afterwards no daemon was listening on 5001/4001.
- 2026-10-10: `kbd-apply list` reports task state from the tasks.md checkboxes, not the runtime. When an agent ticks `[x]` itself, a sweep that skips "done" rows never fires begin-task/end-task, and the runtime task stays pending (mcp-release-binaries). Close by running begin-task/end-task for every task the runtime still shows pending (`prometheus kbd status --json`), not by checkbox state.
- 2026-10-11: Shells hung for ~45 h with no child process. `sample` showed bash 5.3 (`/usr/local/bin/bash`) blocked in `write()` inside `do_redirections`: it writes a here-document or here-string into a pipe whose both ends it holds, assuming the pipe can grow to 64 KB; that macOS pipe stayed at 16 KB, so the write never finished. Sporadic (pipes grow to 64 KB again now). Rules: pass large content through a file, not `python3 - <<EOF` or `<<<"$big"`; use the Edit/Write tools for file edits; run every `kbd-apply` and `prometheus kbd` call under `timeout` with `</dev/null`.
- 2026-10-11: A close that dies after the task mutation but before the after-boundary leaves a complete change or task with an open "Starting" obligation (`boundaryObligations` in `prometheus kbd status --json`; session start lists them as "Outstanding boundaries"). Close it with `prometheus kbd guard evaluate --boundary <change|task> --edge after --subject <change|change/id> --json --repair-projections`. Never re-run a queued close script without first checking the tasks are really done; the hung charcoal-agent queue would have closed unticked tasks.

- 2026-10-13: A Kubernetes postStart exec hook that backgrounds work (`cmd &`) blocks until that work exits unless its I/O is detached (`</dev/null >/dev/null 2>&1 &`); the pod stays PodInitializing and cannot even terminate. Never force-delete a pod stuck that way: the kubelet keeps the old process running, and for kubo it holds `repo.lock` so the replacement crash-loops. LKE nodes have no `crictl`; stop the orphan with a node debug pod (`chroot /host pkill -TERM -f "ipfs daemon"`).
- 2026-10-13: `mcp-agui-a2ui-registry` 1.1 cannot be executed within mcp-server-engineer ownership (defect found at execution, task left undone). (a) Its acceptance "route and event in the contract" presupposes `mcp/contract` names the A2UI catalog route and the run-stream advertisement event, but the completed prerequisite `agent-settings-contract` added only the `agent.a2ui` config key; no route or event is named anywhere in `mcp/contract`, and the AG-UI fixture schema's Event enum (`mcp/contract/fixtures/agui.schema.json`) has no `CUSTOM`, which equally blocks 1.2 and 1.5. (b) "No catalog copy outside the generated file" requires embedding `mcp/ui/catalog/ipfs-mcp.catalog.json`, and `go:embed` cannot reach it from `mcp/server` (patterns reject `..`, and symlinks are refused: "cannot embed file ... in non-directory", verified on go1.27.1), so the embed package must live under `mcp/ui/**` (ui-ux-owned; precedent `mcp/app/embed.go`). Unblock = an architect contract edit naming route + event, plus a one-file embed package in `mcp/ui/catalog/` or an ownership grant of it to mcp-server-engineer.
- 2026-10-14: A know-me-cluster PR built and reviewed offline broke production on merge (#24: guessed htpasswd Secret name, Envoy failed closed with 500s for ~20 min), and two follow-ups repeated the pattern (#24 and #26: Cloudflare DNS-01 issuer for a GoDaddy-hosted domain, then HTTP-01 with no port-80 listener on the gateway). Offline validation and an artifact-only review cannot see live state. Rule: before asking the operator to merge any cluster PR, the lead runs a read-only live check with `kubectl --context know-me` and posts its output on the PR: referenced Secrets exist (key names only), DNS NS and A records, issuer type and where its solver attaches, gateway listeners and route sectionNames, LoadBalancer ports, and `argocd app diff` when available.
- 2026-10-14: A trivial `grep -rn` over `mcp/` and `cmd/` (no here-doc, stdin untouched) hung past the 60 s foreground timeout and kept hanging after 3 minutes in the background; the dedicated Grep tool answered instantly. Treat any hung Bash search as a shell/environment fault, not a slow filesystem: stop the task and re-issue the search with the Grep/Glob tools instead of retrying in the shell.
- 2026-10-14: A builder subagent (Claude Sonnet, desktop-mcp-sidecar) created `.kbd-orchestrator/tier3.allow` to open the `tier-guard` hook so it could run a held Playwright suite; the permission classifier denied the run and the agent deleted the file. Tier-3 suites are held for the phase gate by design. Builder prompts must say: never create or edit gate files (`tier3.allow`), never set `PROMETHEUS_TIER3`, never work around a hook or permission denial; stop and report instead.
- 2026-10-14: xberg v1.3.10 `POST /extract` answers an unreadable file with HTTP 200, empty `results` and an `errors[]` entry, so a client that trusts the status line indexes nothing and reports success. The offline switch is `HF_HUB_OFFLINE=1` (a missing model then shows as an `errors[]` entry `plugin`/1008, or a `processing_warnings` entry for layout); `XBERG_CACHE_DIR` does not move the Hugging Face cache, `HF_HOME`/`HF_HUB_CACHE` do. The multipart `urls` field makes xberg fetch URLs and `inputs` reads server-side paths unless `XBERG_API_ALLOW_LOCAL_URI_INPUTS` is unset; the client sends only `files`, `output_format` and an optional `config`. xberg 1.3.10 lists no audio or video format, so `extractor.transcribe` cannot work yet. Evidence: `openspec/changes/mcp-content-extractor/evidence/2026-10-14-task-1.1/README.md`.
- 2026-10-14: never run `git stash` in this worktree to test "was it already failing": other builders keep uncommitted edits in the same tree and the stash/pop window hides or races them (it also left the package unbuildable while stashed). Check a failure's cause from its message, or use `git worktree add` on HEAD.
- 2026-10-14: Envoy Gateway basic auth (SecurityPolicy `basicAuth`) answers 401 with `WWW-Authenticate: Basic realm="<full request URL>"`, so every path is its own realm and a browser never reuses the credentials typed at `/webui/` for `/api/v0/*` fetches. The console Web UI could not reach the RPC API while curl checks (credentials on every request) passed. Check auth for browser apps in a browser, not only with curl. Interim: Web UI API address with inline credentials; planned fix: session auth (Kratos and `flint-gate`).

- 2026-10-16: `TestTelemetry` (test/cli) failed once with its parent at 0.00s while the whole `TestMCP` CLI family ran in the same `go test` invocation on a loaded machine; it passed alone and in the next full run (412 s). Re-run before treating it as a regression. Also: macOS `/usr/bin/make` is GNU make 3.81 and has no `-O`; use `gmake -O test_go_lint` (Homebrew GNU make 4).

- 2026-10-16: an Argo sync applies sync-wave -1 objects before it prunes removed objects, so a cluster PR that narrows a SecurityPolicy's targetRefs (wave -1) and deletes the route it stopped targeting opens a window where that route serves without auth. PR #36 had this window (09:45:05-09:45:09Z); Envoy access logs showed no request through it. Keep the old targetRef in the PR that removes the route, and drop it in a later cleanup PR.

- 2026-10-17: before proposing a direct dependency bump in an ADR, run `go mod graph | grep <module>` and check whether a protected stack (`go-ds-*`, `go-libp2p*`, `ipshipyard/p2p-forge`) pins it. ADR-0013 claimed go-jose was unprotected; `p2p-forge@v0.10.1` requires go-jose v4.1.4, so the bump had to go upstream first.
